# 事件卡系统与内容生产方案

`STATUS=STRUCTURE_LOCKED_CONTENT_PENDING / IMPLEMENTATION=NOT_STARTED / SOURCE=REFERENCE_REUSE_AUDIT,D-CORE1..5,D-WORLDFEEDBACK0..6,D-ACTIONS1..2,D-WORK1..3,D-LEARN1,D-INVEST1,D-ACTING1,D-REST1,D-ECON0..9,D-DEBT1..3,D-INDUSTRY1..6,D-MARKET1,D-AUCTION1,D-RESOLUTIONBOUNDARY,D-ABILITYRESOLUTION1,D-COMBAT1..D-COMBAT6K,D-EVENT1..18`

事件卡是本项目的内容骨架：日常行动、调查、黑市交易、污染、经济危机、非凡成长和世界变化都要通过事件卡让玩家看见并作出选择。`D-EVENT1..18` 已锁定首版规模、弹出密度、交互、待处理、到期、模型与原著边界、候选池、内容配比、单卡解析、信息公开、重复控制、连环路线和死亡入口；尚未锁定的是117张卡的逐卡文案、数值、原著锚点、具体权重/冷却周数和小模型参数。

`D-WORLDFEEDBACK0..6` 已锁定持续世界动态、逐行动结果条/纪事、三层知识投影、可知因果标注、首版有限离屏模拟和即时/延迟/潜伏后果。事件卡只是反馈载体之一：没有满足卡片条件时，行动仍通过结果条和纪事得到回应；满足条件时才按现有候选池与“一次最多一张阻塞卡”规则生成卡片。暂时不可见的事件实例可以存在于 Main 权威状态，但不能把标题、真实参与者、原因或后果泄露给 Renderer。

## 1. 参考项目的实际事件系统

### 1.1 事件卡不是单一池

《汴京梦华》把事件拆在多个数据文件，再由 `js/events_core.js` 调度：

| 参考池 | 当前快照的静态定义数 | 作用 |
|---|---:|---|
| `events_life.js` | 18 | 普通生活、士林、市井和人际事件 |
| `events_court.js` | 15 | 中枢和党争事件 |
| `events_local.js` | 42 | 地方危机与政务事件 |
| `events_royal.js` | 52 | 皇室和禁中秘闻 |
| `events_regional.js` | 13 | 区域差异事件 |
| `events_manage_*.js` | 195 | 按职业/机构定向的主动理政事件 |
| `events_chain.js` | 30 条连环案、每条 3 个阶段 | 跨月份的长线调查与高潮 |

按当前文件的 `id`/`label` 静态计数，至少有 **365 个事件定义和 781 个选项文本**；运行时还会生成刺杀、商人、请愿、辩论等微型事件。这个数量级说明：要支撑长期周目，不能只写十几个“主线事件”，必须同时有普通事件、情境事件、风险事件、连环事件和世界脉冲事件。

### 1.2 调度器做了什么

参考调度器有三条入口：

1. **主动行动入口**：按身份/职业筛选专属池，先过触发条件，再按权重抽取；同类事件有冷却。
2. **微型事件入口**：从刺杀、求见、商人、请愿、家庭和职业雷达中抽取；类型有独立冷却和重复衰减。
3. **被动时间入口**：先处理连环案阶段，再从生活/中枢/皇室/地方/区域池筛选；事件概率有 `pity` 保底、权重衰减和角色状态修正。

连环案会把阶段、触发时间、动态 NPC 和 payload 写入状态；弹出下一阶段前重新验证参与者是否仍有效，验证失败则安全终止，不让“死者继续说话”。完成或中断的案件还写入历史唯一标记，避免同一案无限重演。

### 1.3 参考 UI 的真实形态

`renderEventUI` 动态创建全屏遮罩，在中央显示约 550px 卡片：彩色标题栏、长描述、纵向选择按钮。按钮点击后关闭卡片、执行选项、写日志，再做统一状态检查和 UI 刷新。连环案阶段复用同一张卡，只替换标题、描述和选项。

这套信息层次值得保留：玩家先读情境，再选行动，结果回到日志。但是参考实现有明确技术债，不能直接拿来：

- 事件对象携带 `function trigger/desc/execute`，内容和规则耦合；
- 直接修改全局 `gameState`，没有事务和 exactly-once；
- 用 `innerHTML` 放入描述和选项，不能承受模型输出；
- 使用 `Math.random()`，无法可靠重放；
- 长日志容易把大量世界变化灌到主界面；
- 冷却/事件计数保存在脆弱的 localStorage 状态中。

## 2. 本项目事件卡生命周期

事件卡必须是“内容数据 + 引擎解析 + 统一结算”的组合，不是可执行脚本：

```text
候选生成 → 条件/可见性校验 → 权重/冷却/多样性抽取
      → 持久化事件实例 → 玩家看到事件卡
      → 选择一个选项 → Main 预检并结算
      → 写入回执、后果、线索、知识和事件历史
      → 生成后续卡/连环阶段/周摘要 → 返回周舞台
```

所有实例都有 `eventInstanceId`、定义版本、周次、来源、随机流游标和状态（`QUEUED/OPEN/RESOLVED/EXPIRED/CANCELLED`）。卡片打开后先持久化“待选择”状态；重复点击只返回原回执，崩溃恢复后继续同一张卡，不重新抽卡。

### 2.1 事件来源优先级与抽取原则（已锁定）

以下优先级用于避免一周弹出一堆互相覆盖的卡；筛选后叠加行动、状态、知识、冷却、多样性和保底修正，再由确定性随机流加权抽取：

1. 资源归零、死亡、明确终局等阻塞事件；
2. 已到期的连环案阶段或玩家行动产生的必达结果；
3. 黑市交易、季度拍卖、财务危机等玩家当前操作结果；
4. 调查/学习/工作/休养触发的情境事件；
5. 周脉冲抽到的世界事件和背景新闻。

同一时刻只打开一张阻塞式事件卡；其余合格事件进入已确定的最小待处理事件列表（正式实现名称待定），在周摘要或纪事抽屉中按优先级、到期时间和玩家相关性展示。背景世界可以继续有摘要，但不能抢走当前决策焦点。

### 2.2 事件类型

第一版建议保留六类，不把所有内容都叫“随机事件”：

| 类型 | 例子 | 结算入口 |
|---|---|---|
| `ACTION_RESULT` | 工作收入、学习发现、休养反应 | 确定性结果或普通判定 |
| `INVESTIGATION` | 线索、目击者、跟踪、神秘地点 | 普通判定，条件满足时进入战斗 |
| `CHAIN_STAGE` | 跨周调查、人物关系和阶段高潮 | 阶段 payload + 普通判定/战斗 |
| `THRESHOLD` | 污染、资源归零、债务和生活危机 | 原因声明的 `onZero` 或事件选项 |
| `MARKET` | 黑市上架、购买、出售、拍卖 | 交易合同 + 风险事件 |
| `WORLD_PULSE` | 组织、NPC、地区和原作时代变化 | 世界脉冲确定性更新 + 可选玩家响应 |

## 3. 事件卡数据合同（提案）

以下字段是建议的最小公共结构；目录和接口目前尚未创建。

### 3.1 卡片定义

| 字段 | 作用 | 约束 |
|---|---|---|
| `id`、`schemaVersion` | 稳定身份与迁移 | 唯一；版本变更不能复用旧语义 |
| `kind`、`tags` | 类型、途径/序列/经济/风险分类 | 来自白名单，不用任意字符串分支 |
| `sourceRefs` | 原著审计、原创设定、设计稿或素材来源 | 每张卡至少一条可审计来源 |
| `trigger` | 周次/行动/事件/季度/链阶段入口 | 只描述数据条件，不含函数 |
| `eligibility` | 角色、知识、关系、资产、地点、状态和可见性条件 | 由规则引擎解释；不满足则不入池 |
| `weight`、`cooldown`、`diversityGroup`、`pityGroup` | 抽取、冷却和重复控制 | 使用行动级可重放随机流 |
| `presentation` | 标题、引导语、正文块、地点/人物引用、语气标签 | 结构化文本；白名单渲染 |
| `choices[]` | 玩家选项集合 | 每项有稳定 ID、可见条件、硬成本和结算引用 |
| `continuation` | 后续事件/链阶段、延迟、过期和 payload schema | 只能写入受校验的事件状态 |
| `visibility` | 玩家、组织、角色或世界可见层级 | 经 `KnowledgeProjection` 过滤 |

### 3.2 选项定义

每个选项至少包含：`id`、玩家可见的 `label`、`visibleWhen`/`disabledWhen`、`costPreview`、`targetSelector`、`resolutionMode`、`resolutionRef` 和 `nextRefs`。`resolutionMode` 只从 `NONE/CHECK/COMBAT/TRADE` 中选择：

- `NONE`：确定性选择，例如接受一条公开消息；
- `CHECK`：调用统一 d100 四档普通判定，修正直接相加；
- `COMBAT`：进入已锁定的双阶段战斗转盘，不能用普通判定替代；
- `TRADE`：调用经济/黑市合同，交易结果仍由 Main 事务提交。

选项不直接携带 JavaScript 函数，也不直接改角色对象。判定或交易产生的后果必须转换为有序 `ConsequenceItem[]`，资源归零来源必须完整声明 `onZero`；缺字段、未知目标、越界权重或未登记扩展处理器时，内容校验拒绝载入。

### 3.3 连环案字段

连环案至少保存 `chainId`、`stageId`、`scheduledWeek`、`expiresWeek`、`actorRefs`、`payload`、`validateRefs`、`nextStageRefs` 和 `completionState`。阶段卡打开前重新计算可见性和参与者存活/有效状态；玩家放弃、条件失效或事件过期都要写入明确的中断原因，不能静默删除。

## 4. 事件卡 UI

### 4.1 最小事件卡

参考项目“标题 + 描述 + 选择按钮”的低学习成本保留，但卡片增加三条玩家真正需要的信息：

1. **上下文条**：当前周次、地点、牵涉人物/组织、事件类型和是否连环阶段；
2. **事实与规则预览区**：玩家已经知道的线索和知识；每个选项公开精确硬成本、判定难度、当前成功概率和主要可预见后果。必须进入实时战斗才能生成的胜率，在战斗界面精确显示；
3. **选项卡**：标准卡默认2个选项；连环/阈值卡只有定义明确声明时才允许3个。每个选项显示行动意图、能力/物品需求和唯一主要入口 `NONE/CHECK/COMBAT/TRADE`。数值预览不能反向泄露角色未知的原著秘密、幕后身份或隐藏事实。

首版一张卡只处理一个选择；选择后卡片变为结果态，依次展示解决质量、实际因果后果、资源前后值、获得/失去的知识和下一张卡的时间，不自动连弹多张卡。玩家点击“继续”才回到周舞台或下一张已排队卡。

### 4.2 非阻塞事件容器（名称待定）

此前建议的 `EventInbox` 不是用户已设计的功能。`D-EVENT7` 已选择最小待处理事件列表：它放在周摘要/纪事抽屉，最多显示未处理卡、已过期卡、连环案进度、来源和到期周；只有定义声明可操作且条件仍满足时才显示“处理”。它不是第五个行动按钮，也不是第二套行动系统；“收件箱”只作为历史俗称，正式实现名称可另行确定。

### 4.3 访问性和安全

弹层使用共用 `OverlayStack`：焦点圈、Escape 返回、背景 inert、键盘选择和屏幕阅读器标题/描述关联。选项按钮使用结构化文本节点渲染，禁止模型/RAG 文本直接进入 `innerHTML`。事件处理期间禁用重复提交，失败停在原卡并显示可重试状态。

## 5. 内容分层和生产计划

### 5.1 内容包分层

为避免“事件数量多但没有玩法”，每张卡按四层验收：

1. **情境层**：发生了什么，玩家能看到什么；
2. **选择层**：至少两种有意义的行动方向，不能只是“接受/拒绝”的换皮；
3. **解析层**：无判定、普通判定、战斗或交易中的一个明确入口；
4. **后果层**：资源、知识、掌握度、扮演、关系、污染、物品、链阶段或世界变化至少有一项可追溯后果。

经济和黑市卡必须能进入现金/产业/债务/物品账；学习卡必须产生具体知识记录；调查卡必须产生线索或新的可见入口；休养卡必须解释三项状态恢复或风险；战斗卡不能把死亡直接写成普通失败文本。

### 5.4 模板、RAG 与小模型（职责边界已锁定）

“只做模板”可以成立，但模板必须是规则合同，不只是几段可替换文案。每张卡至少固定：`id/kind`、触发与可见条件、来源与时间线、选项 `choiceId`、解析入口（`NONE/CHECK/COMBAT/TRADE`）、硬成本、按顺序执行的 `ConsequenceItem[]`、连环阶段、到期和变体插槽。奖励、惩罚、知识、污染、物品和世界变化只写在合同里，由规则引擎结算。

RAG 只为模板提供经过权限/剧透过滤的原著锚点：人物、地点、组织、途径/序列、时代时间线、已确认的行为边界和禁写项，并附来源回执。小模型只在这些锚点和模板插槽内生成标题、描述、氛围、目击细节等叙事变体；不能新增角色真相、配方/真名、数值、难度、选择、奖励、惩罚、事件 ID 或隐藏信息。模型生成失败或校验不通过时，回退到固定作者文本，不重新抽取或重掷结果。

已锁定的工程形态是“作者/构建期生成变体，运行时只从已审核变体中按行动级随机流选择”。这样仍有多样化，但同一事件实例可重放、无模型时可运行、原著边界可审计；运行时即时生成不进入第一版。

### 5.2 参考规模与我们的分阶段目标

参考项目 365 张静态卡、781 个选项和 30 条三阶段连环案只能作为容量证据，不是复制目标。新项目建议分三档，最终由用户选择：

| 档位 | 独立事件卡 | 连环案 | 适用结果 |
|---|---:|---:|---|
| A 最小 | 60 | 6 条 × 3 阶段 | 最快可玩，但重复会较早出现 |
| B 已选 | 90 | 9 条 × 3 阶段 | 覆盖普通生活、经济、调查、三途径和风险，内容/工程较平衡 |
| C 丰富 | 120 | 12 条 × 3 阶段 | 重复压力最低，但会明显推迟第一版内容完成 |

首版目标已锁定为 90 张独立事件卡 + 9 条三阶段连环案（27 张阶段卡，合计117张定义）。S0/S1 仍只使用12张 fixture 卡和1条三阶段 fixture 链验证引擎；真实内容按“普通/经济 → 调查 → 途径 → 风险/连环”逐包加入，不等待全部卡片才验证。A/C只保留为容量对照，不是当前目标。

### 5.3 第一版内容包分布（已锁定）

- 30 张普通生活/职业/关系卡；
- 15 张经济、产业、债务和黑市卡；
- 20 张调查/线索/神秘接触卡；
- 15 张占卜家、观众、猎人途径相关卡；
- 10 张污染、资源归零、危险和战斗入口卡；
- 9 条三阶段连环案，共 27 张阶段卡。

黑市和季度拍卖至少要有独立的浏览、上架、购买、出售、拍卖开放和交易后果卡；不能只做一个“打开商店”按钮。具体挂牌时长、手续费、赃物风险、NPC 竞争和竞价规则仍按经济 Grill 另行锁定。

## 6. 事件抽取与多样性验收（原则已锁定）

- **条件正确**：不同序列、知识、职业、资产、污染和关系不会看到越权卡；不可见卡不以“隐藏按钮”泄漏标题或结局。
- **重复控制**：同一 `diversityGroup` 有冷却和衰减；连续低价值重复行动不能无限刷同一张卡；连环阶段不重复生成。
- **因果连续**：上一张卡的 `nextRefs`、payload、线索和 NPC 状态可在重启后继续；参与者死亡/失效会按声明中断。
- **结果可重放**：同一事件实例、选项和随机流得到同一结果；重复点击返回同一 receipt。
- **信息安全**：RAG 只能提供来源候选和收据；模型不能生成新的事实、难度、选项后果或事件实例 ID。
- **玩家可读**：主舞台一次只突出一张阻塞卡；世界变化先摘要后展开；卡片的每个选项都能追溯到一个解析入口和结果。
- **内容完整**：每个真实卡片通过 schema lint、来源检查、选项可达性、后果覆盖和人工原著/题材审查。

## 7. 已锁定的事件基础问题

以下七题已由用户确认；它们只锁定内容容量、弹出节奏和基础承载，不替代后续卡片结构与生成方式 Grill：

### `D-EVENT1` 第一版事件卡规模 — `LOCKED`

- **A**：60 张独立卡 + 6 条三阶段连环案；最快，但重复压力高。
- **B（已选）**：90 张独立卡 + 9 条三阶段连环案；内容量和开发周期平衡。
- **C**：120 张独立卡 + 12 条三阶段连环案；内容最稳，但第一版明显延期。

### `D-EVENT2` 周事件弹出密度 — `LOCKED`

- **A（已选）**：一次行动/周脉冲最多出现一张阻塞式选择卡，其余进入已锁定的最小待处理事件列表或纪事摘要；保留参考项目“选择有重量”的节奏。
- **B**：允许同一行动连续弹出多张卡；戏剧密度高，但容易打断玩家并增加状态恢复复杂度。
- **C**：只有调查、连环案和阈值才弹卡；最清爽，但工作/学习/黑市的后果反馈会变薄。

两题只锁定内容量和弹出节奏，不锁定具体卡片文案、原著事件、价格或能力数值。

## 8. 已锁定的事件卡基础交互
