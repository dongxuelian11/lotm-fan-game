# 事件卡系统与内容生产方案

事件卡是本项目的主要轻量内容骨架：日常行动、调查、黑市交易、污染、经济危机、非凡成长、人物交互和世界变化都通过卡片让玩家看见并作出选择，而不是再建立一套庞大的传统任务系统。游戏没有覆盖全部周目的单一主线；共享事件、连环案和世界模拟构成公共剧情层，每条途径另有“接触—早期成长—势力/组织冲突—终局”四阶段弧。势力阶段允许合作、拒绝、敌对或保持独立，不强制加入组织。既有117个定义只是普通人和低序列阶段的第一批共享内容底座，不是首版或完整游戏的数量上限。事件内容先按普通人、序列9、序列8……序列0分层；同一序列允许22条途径复用结构模板，但每条途径必须拥有自己的事件内容、选项、能力入口与后果，绝不让全途径共用一套成品事件。

世界在每次行动后给出结果条或纪事反馈。本周行动点耗尽后，系统先逐张处理该行动产生和本批已经排队的阻塞卡，再立即执行完整周脉冲并推进一周，不增加现实时间倒计时或多余的“结束本周”确认。事件卡是主要内容载体，但不是每次按钮都必须强行弹卡：没有满足卡片条件时，行动仍通过结果条和纪事得到回应；满足条件时才按候选池与“一次最多一张阻塞卡”规则生成卡片。工作、学习、调查、休养四个行动都能触发事件，也都能经事件中的实际行为推进扮演；按钮本身不直接赠送扮演进度。世界消息继续区分已确认、传闻/推测和暂不可见三层；本次周脉冲的全部可知更新都进入公开列表，暂不可见事件则不能把标题、真实参与者、原因或后果泄露给界面。

普通人阶段保持大量生活、职业、关系、经济与普通调查事件；成为非凡者后，候选池和内容生产以约70%的非凡相关事件为目标，其余日常内容继续承担身份、资源和关系压力。这个比例是阶段体验目标，不是每周硬配额；精确统计窗口和权重需要用试玩校准。宇宙级恐怖只出现在少数内容高峰，不能成为普通周脉冲的常规噪声。

每个出身至少提供1个专属开局事件和2类可复用事件钩子，并服从相同的数据合同、知识可见性、冷却和持久化规则。正式117个共享定义按普通/职业、经济/黑市、调查/线索、共享非凡、风险/战斗和连环案分包制作。首个正式事件包是调查/线索类别的30个定义：24张独立闭环卡和2条各三阶段的连环案；两条连环案独立维护线索进度，阶段完成后才生成下一阶段且不占独立卡触发位。

内容包必须提供来源、数值模拟和风险说明；自动平衡只作参考，致命风险必须在选择前由已审核内容明确声明。任何玩家可见事件在入池前必须具备固定事实、规则、选项、成本/奖励、来源记录和至少一份审核过的回退文本；模型不能补齐缺失规则或因果。当前代码只有事件底座、少量试玩 fixture 和一条 fixture 连环案，正式117个定义及逐途径成长弧尚未实现。

## 0. 当前锁定的体验参数

- 开局当前居住地固定贝克兰德，出生地仍从四城独立选择；当前城市及直接相关人物/组织高精度推进，远方只推进时间线、组织态势和公开消息；
- 允许轻量主动迁居，但不做地图和路线模拟；只有已解锁且具备审核事件池的目的地可用，迁居消耗一次主要行动和明确旅费，再用事件卡结算城市切换；
- 与当前年代相关的原著人物都有稳定身份记录，只有进入当前地区、组织、事件或因果范围的人物才加载完整阶段图；条件真实重叠时可以规律直接互动；
- 原著人物只能因已经展示并完成结算的事件、战斗、玩家因果或原著基线事实死亡，不能被离屏随机模拟杀死；重大时间线分支手工设计，普通支线使用确定性取消、替代、组织反应或延期；
- 人际关系使用“关系类型＋定性态度＋近期原因”；组织只保存一条综合关系阶段和一个当前议程；
- 普通人阶段阻塞卡目标为每周1—2张，成为非凡者后为2—3张；这是试玩密度目标，不是逐周配额；
- 已经生成的待办选择必须全部解决后才能继续主要行动或结束本周；一次仍只显示一张，处理待办不额外消耗行动点；
- 周脉冲展示全部玩家当前可知的人物、组织和地区更新，不按固定条数截断；
- 每条途径采用四阶段成长弧，但组织加入完全自愿，途径不得绑定组织，并必须存在无需正式入会的晋升路线；
- 所有场景可以使用构建期审核通过的叙事变体；每个可复用模板以1份固定回退文本加8份审核变体为基准，事实、规则、选项和结果始终相同；
- 周目不设现实分钟或小时目标；本周行动点耗尽、已生成阻塞卡清空后立即周结算。晋升随序列提升总体减速，序列0结清即时后果后进入周目总结与多轴评价；序列4只是中盘转折，死亡或其它不可逆终局可以提前结算；
- 每张阻塞事件必须属于普通人或一个明确的精确序列内容层；低序列事件不会继续进入高序列抽取池。持续存在的生活/关系因果若需要在晋升后继续，必须转换成当前序列对应的新事件版本，而不是让序列0继续处理序列9规模的卡；
- 同一精确序列可以让22条途径复用`SequenceEventTemplate`，但每条已发布途径必须提供独立`PathwayEventVariant`；变体至少改变事件切入、一个能力/选择路线和一项后果或扮演证据，不能只换能力名和文案；
- 不设置每局战斗场次上限、下限或配额；只有事件事实、敌意、地点、资格与玩家选择真正需要时才进入战斗，同一事件链可以因选择完全避战或连续产生多场冲突；
- 宇宙级恐怖以手工高峰为主，也可由高污染、高序列、重大仪式或原著级危机的明确阈值触发审核事件；不使用无条件低概率随机惊吓；
- 第一条开发验证弧采用贝克兰德城市调查，已锁定为“奥黛丽·霍尔 + 轻量角色梅芙·库珀 + 黑夜教会值夜者 + 工业压迫掩盖低层非凡危害”的三阶段调查链。奥黛丽按原著阶段决定本人或可信中间人出场；值夜者不是通关钥匙或强制入会入口；结局分别记录救援、追责、危害处置和奥黛丽关系，不能用一个成功/失败值互相覆盖。

## 1. 参考项目的实际事件系统

### 1.1 事件卡不是单一池

《汴京梦华》把事件拆在多个数据文件，再由 `js/events_core.js` 调度：

| 参考池 | 当前快照的静态定义数 | 作用 |
|---|---:|---|
| `events_life.js` | 18 | 普通生活、士林、市井和人际事件 |
| `events_court.js` | 15 | 中枢和党争事件 |
| `events_local.js` | 42 | 地方危机与政务事件 |
| `events_royal.js` | 52 | 皇室和禁中秘闻 |
| `events_regional.js` | 13 | 区域差异事件 |
| `events_manage_*.js` | 195 | 按职业/机构定向的主动理政事件 |
| `events_chain.js` | 30 条连环案、每条 3 个阶段 | 跨月份的长线调查与高潮 |

按当前文件的 `id`/`label` 静态计数，至少有 **365 个事件定义和 781 个选项文本**；运行时还会生成刺杀、商人、请愿、辩论等微型事件。这个数量级说明：要支撑长期周目，不能只写十几个“主线事件”，必须同时有普通事件、情境事件、风险事件、连环事件和世界脉冲事件。

### 1.2 调度器做了什么

参考调度器有三条入口：

1. **主动行动入口**：按身份/职业筛选专属池，先过触发条件，再按权重抽取；同类事件有冷却。
2. **微型事件入口**：从刺杀、求见、商人、请愿、家庭和职业雷达中抽取；类型有独立冷却和重复衰减。
3. **被动时间入口**：先处理连环案阶段，再从生活/中枢/皇室/地方/区域池筛选；事件概率有 `pity` 保底、权重衰减和角色状态修正。

连环案会把阶段、触发时间、动态 NPC 和 payload 写入状态；弹出下一阶段前重新验证参与者是否仍有效，验证失败则安全终止，不让“死者继续说话”。完成或中断的案件还写入历史唯一标记，避免同一案无限重演。

### 1.3 参考 UI 的真实形态

`renderEventUI` 动态创建全屏遮罩，在中央显示约 550px 卡片：彩色标题栏、长描述、纵向选择按钮。按钮点击后关闭卡片、执行选项、写日志，再做统一状态检查和 UI 刷新。连环案阶段复用同一张卡，只替换标题、描述和选项。

这套信息层次值得保留：玩家先读情境，再选行动，结果回到日志。但是参考实现有明确技术债，不能直接拿来：

- 事件对象携带 `function trigger/desc/execute`，内容和规则耦合；
- 直接修改全局 `gameState`，没有事务和 exactly-once；
- 用 `innerHTML` 放入描述和选项，不能承受模型输出；
- 使用 `Math.random()`，无法可靠重放；
- 长日志容易把大量世界变化灌到主界面；
- 冷却/事件计数保存在脆弱的 localStorage 状态中。

## 2. 本项目事件卡生命周期

事件卡必须是“内容数据 + 引擎解析 + 统一结算”的组合，不是可执行脚本：

```text
读取当前普通人/精确序列层 → 选择该层的SequenceEventTemplate
      → 选择当前途径的PathwayEventVariant
      → 条件/可见性校验 → 权重/冷却/多样性抽取
      → 持久化事件实例 → 私有匹配该变体内的隐藏选项
      → 只投影最终事件内容和已匹配选项 → 玩家看到事件卡
      → 选择一个选项 → Main 预检并结算
      → 写入回执、后果、线索、知识和事件历史
      → 生成后续卡/连环阶段/周摘要 → 返回周舞台
```

所有实例都有 `eventInstanceId`、定义版本、周次、来源、随机流游标和状态（`QUEUED/OPEN/RESOLVED/EXPIRED/CANCELLED`）。卡片打开后先持久化“待选择”状态；重复点击只返回原回执，崩溃恢复后继续同一张卡，不重新抽卡。

### 2.1 四类事件容器

正式事件运行时不把所有未完成内容塞进一个 `pendingEvents[]`。内部至少区分四类：

1. **当前阻塞事件**：全局最多1张，已经持久化并等待玩家选择；存在时不能提交新的主要行动；
2. **待办选择**：条件已满足、必须在下一个主要行动或周结束前处理的可操作事件，按优先级、到期时间和玩家相关性排序；系统逐张提升为当前阻塞事件，直到本批清空；
3. **计划事件**：尚未到触发时间或仍等待条件的内部日程，不向玩家泄露标题、参与者或真实原因；
4. **纪事消息**：不需要玩家选择的行动结果、世界新闻、取消原因和已知后果，只进入世界推演或纪事。

四类内容使用不同状态和迁移，不通过标题或 UI 位置猜测类型。当前原型的“待处理最多3条、统一一周过期”和固定触发概率只是 fixture，不能成为正式规则；正式上限、过期后果和事件密度由本轮问题批次确定。

### 2.2 事件来源优先级与抽取原则

以下优先级用于避免一周弹出一堆互相覆盖的卡；筛选后叠加行动、状态、知识、冷却、多样性和保底修正，再由确定性随机流加权抽取：

1. 资源归零、死亡、明确终局等阻塞事件；
2. 已到期的连环案阶段或玩家行动产生的必达结果；
3. 黑市交易、季度拍卖、财务危机等玩家当前操作结果；
4. 调查/学习/工作/休养触发的情境事件；
5. 周脉冲抽到的世界事件和背景新闻。

同一时刻只打开一张阻塞式事件卡；其余已经生成且需要玩家选择的事件进入待办列表，并按优先级逐张打开，清空前不能提交下一个主要行动或结束本周。计划事件不会因为尚未到期而阻塞，背景世界变化进入纪事。内容校验必须保证同一结算批次有限、没有零成本自生成循环，避免事件链无限阻塞。

### 2.3 事件类型

第一版建议保留六类，不把所有内容都叫“随机事件”：

| 类型 | 例子 | 结算入口 |
|---|---|---|
| `ACTION_RESULT` | 工作收入、学习发现、休养反应 | 确定性结果或普通判定 |
| `INVESTIGATION` | 线索、目击者、跟踪、神秘地点 | 普通判定，条件满足时进入战斗 |
| `CHAIN_STAGE` | 跨周调查、人物关系和阶段高潮 | 阶段 payload + 普通判定/战斗 |
| `THRESHOLD` | 污染、资源归零、债务和生活危机 | 原因声明的 `onZero` 或事件选项 |
| `MARKET` | 黑市上架、购买、出售、拍卖 | 交易合同 + 风险事件 |
| `WORLD_PULSE` | 组织、NPC、地区和原作时代变化 | 世界脉冲确定性更新 + 可选玩家响应 |

### 2.4 世界模拟与人物层级

世界模拟只推进会影响玩家、事件资格或后续因果的状态，不做全城逐人逐帧模拟：

1. **原著关键人物**：使用稳定角色 ID、手工设计的阶段状态、动机、关系、位置/可用性和专属事件卡。原著人物必须真实存在于可交互世界中；只要玩家行为和既有因果允许，他们也可以受伤或死亡。
2. **轻量具名角色**：拥有稳定 ID 和确定性姓名，只保存角色槽位、当前关系阶段、可用性、所属、最近原因与当前事件所需状态。姓名来自已审核内容或确定性名字池，不由运行时模型临场创造新的世界事实。
3. **组织与群体**：原著主要组织使用轻量聚合状态，每个组织只记录一条综合关系阶段、一个当前议程、地区活动和可触发事件；玩家默认没有正式组织归属，只有事件卡中的明确选择才能加入，同一时间最多一个主要正式组织。普通人群只用聚合状态，不逐个建立角色脑。

关系不使用隐藏的万能好感数值对玩家下结论，而保存关系类型、定性态度与近期原因。每次行动先提交事实与后果，再让受影响角色和组织更新状态，最后重新筛选事件。原著时间线只作为未受干预时的初始基线：一旦玩家导致人物死亡、失去资格、改变归属或破坏关键条件，所有带该依赖的卡片和组织议程都必须重新验证、取消或进入已设计的分支，禁止让死者继续出场或照播已经失效的原作结果。

关键人物不使用自由生成式“角色脑”。每名关键人物拥有手工阶段图：阶段定义当前目标、允许采取的行动、禁止项、进入/离开条件和专属事件引用；在当前阶段允许的行动集合内，再用可解释的效用评分选择本周意图。评分只读取已经确认的事实、关系、地点、组织压力和近期原因，最终选择及其分数可以调试和重放。轻量角色不运行独立效用循环，只在相关事件、关系或替代角色槽被触发时更新。

组织使用有限阶段图推进一条当前议程，不模拟每名成员或并行派系资源。每个组织行动必须说明受影响地区、人物/角色槽、公开迹象、潜伏后果和下一次重评条件；普通地区只保存会影响事件候选的少量标签与正在发生的事件，不建立全城人口模拟。

### 2.5 一次行动与周脉冲的正式顺序

```text
提交主要行动
  → 结算行动的确定性结果/普通判定
  → 写入资源、知识、线索和领域事实
  → 更新本行动直接影响的人物、组织和延迟后果
  → 抽取至多一张当前阻塞事件，或写入待办/纪事
  → 若仍有主要行动：保存并返回周舞台
  → 若主要行动已耗尽：标记“周脉冲待执行”
  → 先解决当前阻塞事件
  → 执行完整周脉冲并推进日期
  → 重新校验人物、组织、地区、计划事件与连续性依赖
  → 生成周摘要、下一张阻塞事件或待办选择
```

因此，最后一次行动触发的阻塞卡必须在完整周脉冲之前解决；日期不会先前进再跳过周脉冲。事件打开期间世界时间不继续偷偷推进。每个阶段都是独立提交边界：崩溃后从最近已提交状态继续，不重抽事件，也不重复应用后果。

## 3. 事件卡数据合同（提案）

以下字段是正式内容目标的最小公共结构。当前原型已建立公开投影和12张 `PLAYTEST_FIXTURE` 卡/一条三阶段fixture链所需的窄实现，但不等于全部正式字段和117张内容已经完成。

### 3.1 卡片定义

| 字段 | 作用 | 约束 |
|---|---|---|
| `id`、`schemaVersion` | 稳定身份与迁移 | 唯一；版本变更不能复用旧语义 |
| `kind`、`tags` | 类型、经济、风险与内容分类 | 来自白名单，不用任意字符串分支 |
| `sequenceTemplateId`、`exactSequence` | 所属序列模板与精确内容层 | 阻塞事件只能属于普通人或一个精确序列；最终事件禁止跨序列通用 |
| `pathwayVariantId`、`pathwayId` | 当前途径的独立事件变体 | 同序列可共享模板，但成品事实、选择与后果必须读取本途径变体 |
| `sourceRefs` | 原著审计、原创设定、设计稿或素材来源 | 每张卡至少一条可审计来源 |
| `arcRefs` | 共享层、途径弧、组织弧、人物弧或终局弧 | 一张卡可服务多个弧，但每个关键推进只有一个权威阶段键 |
| `trigger` | 周次/四类行动/事件/季度/链阶段入口 | 只描述数据条件，不含函数 |
| `eligibility` | 角色、知识、关系、资产、地点、状态和可见性条件 | 由规则引擎解释；不满足则不入池 |
| `actorRefs`、`continuityDeps` | 参与者与必须仍成立的世界事实 | 发卡前和结算前都重验；失效时按声明取消或改道 |
| `weight`、`cooldown`、`diversityGroup`、`pityGroup` | 抽取、冷却和重复控制 | 使用行动级可重放随机流 |
| `presentation` | 标题、引导语、正文块、地点/人物引用、语气标签 | 结构化文本；白名单渲染 |
| `choices[]` | 所有角色都可能获得的基础选项 | 每项有稳定 ID、可见条件、硬成本和结算引用 |
| `opportunitySlots[]` | 本事件允许能力介入的具体机会槽 | 必须写明对象、目标、可改变范围与后果接点；不能只有通用能力标签 |
| `specialChoiceBindings[]` | 当前途径/序列变体内部的隐藏特殊选项 | 按能力、掌握度、资源、知识与世界状态匹配；未命中项不进入公开投影 |
| `passiveAbilityHooks[]` | 事件生成后自动检查的日常非凡能力钩子 | 引用[途径日常效果](PATHWAY_DAILY_EFFECTS.md)的稳定能力ID、标签、阶段、优先级、效果和来源说明；不是第二套卡牌系统 |
| `continuation` | 后续事件/链阶段、延迟、过期和 payload schema | 只能写入受校验的事件状态 |
| `onSequenceChanged` | 事件未结时玩家晋升的处理 | 只能选择`RESOLVE_AS_WORLD_RESULT / CANCEL_WITH_RECORD / TRANSFORM_TO_CURRENT_SEQUENCE`；禁止原卡继续跨级抽取 |
| `actingOpportunities` | 哪些选项可能构成何种扮演证据 | 结算时按契合、理解、风险与新意判定，不由触发按钮直接给值 |
| `variantSetId` | 已审核叙事变体集合 | 变体共享同一事实、规则、冷却和推进身份 |
| `visibility` | 玩家、组织、角色或世界可见层级 | 经 `KnowledgeProjection` 过滤 |

### 3.2 选项定义

每个选项至少包含：`id`、玩家可见的 `label`、`visibleWhen`/`disabledWhen`、`costPreview`、`targetSelector`、`resolutionMode`、`resolutionRef` 和 `nextRefs`。`resolutionMode` 只从 `NONE/CHECK/COMBAT/TRADE` 中选择：

- `NONE`：确定性选择，例如接受一条公开消息；
- `CHECK`：调用统一 d100 四档普通判定，修正直接相加；
- `COMBAT`：进入既定的多回合战斗转盘，不能用普通判定替代；
- `TRADE`：调用经济/黑市合同，交易结果仍由 Main 事务提交。

选项不直接携带 JavaScript 函数，也不直接改角色对象。判定或交易产生的后果必须转换为有序 `ConsequenceItem[]`，资源归零来源必须完整声明 `onZero`；缺字段、未知目标、越界权重或未登记扩展处理器时，内容校验拒绝载入。

日常能力在事件实例的事实与基础选项固定后，通过`passiveAbilityHooks[]`自动改变公开信息、风险提示、判定参数、选项资格或结果保护，不增加第五种事件结算模式，也不再询问玩家是否发动。每次触发必须显示能力名、原因和影响；被动效果没有额外硬成本，不能产生未同意的暴露/污染。多个钩子按固定阶段、优先级和叠加规则处理，不能互相生成新的被动钩子或形成无限结算链。带主动成本的能力使用另作为事件主动选项设计，不归入日常被动。

### 3.3 序列事件包、途径变体与隐藏选项

事件先分序列，再分途径，最后才匹配隐藏选项。`SequenceEventTemplate`只能服务普通人或一个`exactSequence`，定义这一位格适合面对的问题规模、参与者槽、冲突骨架、机会槽和结果轴；`PathwayEventVariant`为当前途径另写事件切入、能力路线、选择、代价、扮演证据和后果。它们不是同一张卡上的220个隐藏按钮，而是从一开始就属于不同内容包的成品事件。

变体内部的`specialChoiceBindings[]`至少包含：`bindingId`、`abilityRefs`、`opportunitySlotRef`、`privateConditions`、`choiceRef`、`costRef`、`resolutionRef`、`consequenceRefs`、`priority`和`supersedes[]`。

正式顺序固定为：

```text
读取角色当前普通人/精确序列层
→ 从该序列包中选择模板
→ 装载当前途径的独立事件变体与基础选项
→ 读取已获得能力、掌握度、资源、知识与世界状态
→ 在本变体私有层筛选隐藏绑定
→ 处理高序列覆盖、互斥、优先级与合法目标
→ 自动应用无需选择的日常被动
→ 只把最终匹配的特殊选项并入公开卡片
→ 玩家选择后再次原子校验并按既定引用结算
```

- `exactSequence`是模板发布要求，不能只写“低序列通用”或“半神通用”。角色晋升后只抽取新序列包；继承的旧能力要在新序列事件变体里重新设计用途，不能把旧卡直接带上来。
- 同一序列的路径变体不能只把`abilityRefs`替换掉。至少要改变：玩家怎样进入事件、一个真正不同的选择或目标，以及一项会持续到后续的后果/扮演证据。做不到这些，就说明该模板不适合这条途径，应另建模板。
- 不匹配的选项不得以禁用态、问号、锁图标、灰字条件、选项总数或日志提示泄露。Renderer只能收到已经匹配且玩家可知的最终选项。
- 特殊选项必须改变行动方法、目标、信息、判定、代价或后果中的至少一项；只把同一句话改名、统一加成功率或统一减成本，不算途径差异化。
- 日常能力仍是事件内被动触发：它可自动揭示事实、改变判定、保护后果，或令一个预写隐藏选项满足公开条件；玩家不需要额外点击“发动被动”。有成本、有目标或可能主动暴露的能力才作为特殊主动选项。
- 同一张卡必须保留至少一个不依赖非凡能力的基础路线，除非它本身是已经明确接受的途径专属晋升/仪式事件。

生产层使用`SequenceEventTemplate → PathwayEventVariant → specialChoiceBindings → NarrativeVariant → EventInstance`。模板减少的是结构劳动，不减少途径内容劳动；路径变体及其事件特定后果必须逐项审核，小模型不得自动创造变体、绑定或规则。

#### 序列内容尺度

| 内容层 | 主要事件规模 | 不应继续出现的旧层问题 |
|---|---|---|
| 普通人 | 生计、关系、职业、普通调查、第一次异常接触 | 已掌握非凡能力后的教学型异常 |
| 序列9 | 个人范围的低层非凡案件、能力初用、材料和身份风险 | 纯普通人的无能力教程 |
| 序列8 | 稳定运用新能力、街区风险、早期敌人与连续事件 | 只验证“能力是否存在”的序列9卡 |
| 序列7 | 多目标问题、准备与组合能力、组织注意 | 单一步骤即可结束的入门异常 |
| 序列6 | 身份、渗透、反侦察、跨群体因果 | 仍以普通职业小冲突作为核心威胁 |
| 序列5 | 势力节点、代理人/召唤物/特殊资源、地区危机 | 只影响一个陌生人的一次性小案 |
| 序列4 | 半神位格、城市或大型组织反应、公开神秘后果 | 低层黑市跑腿与入门材料教学 |
| 序列3 | 长时段仪式、历史/大范围结构、跨地区因果 | 只靠一次普通调查闭合的案件 |
| 序列2 | 天使层级冲突、国家/大型城市命运、重大愿望或权柄后果 | 低序列敌人与地方琐事充当主要阻力 |
| 序列1 | 途径顶层准备、锚与大规模世界关系、神战前置 | 可由普通组织程序直接解决的阻塞卡 |
| 序列0 | 晋升、权柄、神性、世界级分歧与周目终局 | 任何以序列9规模问题为主体的事件 |

普通生活和旧关系不会从世界上消失，但高序列阶段只以符合当前位格的方式回归：作为锚、人性、长期责任、身份暴露或大范围因果的一部分，而不是继续要求玩家亲自处理低层跑腿卡。

### 3.4 连环案字段

连环案和途径成长弧至少保存 `chainId/arcId`、`stageId`、`scheduledWeek`、`expiresWeek`、`actorRefs`、`payload`、`validateRefs`、`nextStageRefs` 和 `completionState`。阶段卡入队前、打开前与结算前都要重新计算可见性、参与者存活/有效状态和时间线依赖；玩家放弃、人物死亡、条件失效或事件过期都要写入明确的中断、替代或分支原因，不能静默删除。

### 3.5 事件弧与对话图

本项目使用自定义纯数据图，不把 Ink、Yarn 或运行时模型设为规则依赖。`EventArcDefinition` 只连接稳定的事件/阶段 ID；每个节点仍是一张一次只做一个选择的卡，边由选择、已提交事实、时间窗口或明确中断原因决定。人物对白使用稳定文本 ID、说话者 ID、语气标签和已审核变体集；对白节点不能直接修改状态，状态变化只发生在选择或结算引用上。

条件表达使用白名单谓词和结构化参数，不发明自由表达式语言。内容校验必须遍历所有弧：每个节点能结束、跳转、取消或进入明确分支；不能出现无出口节点、失效角色引用、重复应用的进入效果或永远不可达的选项。

### 3.6 连续性失效处理

每个关键依赖失效时只能进入四种声明结果：

- `CANCEL_WITH_RECORD`：取消并向纪事写入玩家当前可知的原因；
- `REPLACE_ACTOR`：用明确的角色槽替代，但替代者必须拥有新的稳定 ID，不能让死者换名继续说话；
- `BRANCH_TO`：进入已审核的替代事件或弧节点；
- `RESCHEDULE`：条件暂时不满足，按声明的新窗口重新排期。

关键原著分歧使用手工分支；非关键组合可以使用确定性的取消、角色槽替代和组织反应模板。任何自动回退都只能组合已经审核的事实与后果，不能让模型即兴编写新的世界结论。

## 4. 事件卡 UI

### 4.0 世界推演消息与事件卡不是同一容器

参考项目的中间区域持续追加世界日志，选择事件则由页面级全屏遮罩在中央独立弹出。本项目只借鉴这一信息架构，不复制参考代码、文案或素材：

- 中栏是常驻“世界推演”消息面，按时间显示角色可知的世界脉冲与事件结果，不在中栏内嵌选择卡；
- 需要玩家决定的阻塞事件卡使用页面级固定遮罩居中弹出，位于三栏仪表盘之外；打开时后台必须 `inert/aria-hidden`，背景点击和Escape都不能跳过；
- 底部只显示最近一次行动的紧凑回执，避免与中栏世界消息重复；知识、线索和待处理事项保持辅助记录；
- 事件选择不额外消耗行动点，但事件定义中的金钱、物品、状态等硬成本照常结算。

当前原型只实现这套交互的测试纵切。正式117张内容、完整结果态展示、跨重启恢复和桌面壳仍未完成。

### 4.1 最小事件卡

参考项目“标题 + 描述 + 选择按钮”的低学习成本保留，但卡片增加三条玩家真正需要的信息：

1. **上下文条**：当前周次、地点、牵涉人物/组织、事件类型和是否连环阶段；
2. **事实与规则预览区**：玩家已经知道的线索和知识；每个选项公开精确硬成本、判定难度、当前成功概率和主要可预见后果。必须进入实时战斗才能生成的胜率，在战斗界面精确显示；
3. **选项卡**：标准卡默认2个选项；连环/阈值卡只有定义明确声明时才允许3个。每个选项显示行动意图、能力/物品需求和唯一主要入口 `NONE/CHECK/COMBAT/TRADE`。数值预览不能反向泄露角色未知的原著秘密、幕后身份或隐藏事实。

首版一张卡只处理一个选择；选择后卡片变为结果态，依次展示解决质量、实际因果后果、资源前后值、获得/失去的知识和下一张卡的时间，不自动连弹多张卡。玩家点击“继续”才回到周舞台或下一张已排队卡。

### 4.2 待办、计划与纪事入口

待办入口显示本批尚未解决的选择卡、来源、优先级和已知期限，并按顺序把下一张提升为阻塞卡；待办清空前主要行动与周结束保持禁用。计划事件只在其条件成熟后进入待办或纪事，不能提前泄露。纪事保存不可操作反馈、取消/过期记录和连环案进度。三者都不是第五个固定行动按钮，也不是第二套行动系统。

### 4.3 访问性和安全

弹层使用共用 `OverlayStack`：焦点圈、背景 inert、键盘选择和屏幕阅读器标题/描述关联。非阻塞抽屉可按其合同支持Escape返回；阻塞事件卡在解决前禁止Escape或背景点击关闭。选项按钮使用结构化文本节点渲染，禁止模型/RAG 文本直接进入 `innerHTML`。事件处理期间禁用重复提交，失败停在原卡并显示可重试状态。

## 5. 内容分层和生产计划

### 5.1 内容包分层

为避免“事件数量多但没有玩法”，每张卡按四层验收：

1. **情境层**：发生了什么，玩家能看到什么；
2. **选择层**：至少两种有意义的行动方向，不能只是“接受/拒绝”的换皮；
3. **解析层**：无判定、普通判定、战斗或交易中的一个明确入口；
4. **后果层**：资源、知识、掌握度、扮演、关系、污染、物品、链阶段或世界变化至少有一项可追溯后果。

经济和黑市卡必须能进入现金/产业/债务/物品账；学习卡必须产生具体知识记录；调查卡必须产生线索或新的可见入口；休养卡必须解释三项状态恢复或风险；战斗卡不能把死亡直接写成普通失败文本。

### 5.2 模板、RAG 与小模型

内容生产优先制作尽可能多、彼此职责明确的序列模板，而不是少量跨9—0复用的超长脚本。系统区分五层：`SequenceEventTemplate`固定该精确序列的问题尺度、参与者槽、冲突骨架、机会槽和结果轴；`PathwayEventVariant`固定该途径的事件事实、选项、能力入口、代价、扮演证据与后果；`specialChoiceBindings`处理变体内部更细的能力/掌握度/资源门槛；`NarrativeVariant`提供同一规则结果的审核文本；`EventInstance`在周目中绑定具体参与者、世界状态、随机流与唯一推进身份。奖励、惩罚、知识、污染、物品和世界变化只写在规则内容里，由引擎结算。

RAG 只为模板提供经过权限/剧透过滤的原著锚点：人物、地点、组织、途径/序列、时代时间线、已确认的行为边界和禁写项，并附来源回执。小模型只在这些锚点和模板插槽内生成标题、描述、氛围、目击细节等叙事变体；不能新增角色身份、人物生死、配方/真名、数值、难度、选择、奖励、惩罚、事件 ID、组织决策或隐藏信息。模型生成失败或校验不通过时，回退到固定作者文本，不重新抽取或重掷结果。

事件定义、规则字段与可审核内容库采用“作者/构建期生成并审核，运行时按行动级随机流选择”。所有场景都可以从构建期审核通过的变体池选择文案，包括原著人物和途径关键场景，但关键事实与结果保持完全一致。每个可复用模板以1份固定回退文本加8份审核变体为基准；独一无二场景不为凑数强制复用。运行时本地AI可以基于已经确定且玩家可知的事实生成即时描述、传闻措辞和NPC对白，但这些文字不能新增或改写事实、规则、选项、数值、奖励、惩罚、因果、秘密或存档状态；通过校验的即时文本需与事件实例一起保存，以保证读档与复盘一致。无模型、超时或校验失败时回退已审核固定文本。

### 5.3 参考规模与我们的分阶段目标

参考项目365张静态卡、781个选项和30条三阶段连环案只作为“长期游戏需要大事件池”的容量证据，不是复制目标。此前三档只用于选择第一批共享底座，不能被解释为完整游戏事件总量：

| 档位 | 独立事件卡 | 连环案 | 适用结果 |
|---|---:|---:|---|
| A 最小 | 60 | 6 条 × 3 阶段 | 最快可玩，但重复会较早出现 |
| B 已选 | 90 | 9 条 × 3 阶段 | 覆盖普通生活、经济、调查、三途径和风险，内容/工程较平衡 |
| C 丰富 | 120 | 12 条 × 3 阶段 | 重复压力最低，但会明显推迟第一版内容完成 |

第一批共享底座仍为90张独立事件卡＋9条三阶段连环案（27张阶段卡，合计117张定义），主要负责普通生活、经济、调查、世界反馈和序列9前后的入口内容。它不是首版内容上限，更不能沿用到所有序列。后续必须按序列9、8……0分别建立模板包，再为每个已发布途径制作路径变体。S0/S1仍只使用12张fixture卡和1条三阶段fixture链验证引擎；fixture不需要伪装成正式全量覆盖。真实内容逐包加入，但任何路径/序列只有拥有符合自身位格的事件包后才能标为正式可玩。

模板数与玩家可见规则变体数必须分开统计。一个模板覆盖22条途径时，仍需22份独立`PathwayEventVariant`；文案变体不增加玩法内容计数。序列9的首批模板目录和逐途径差异门槛见[序列9事件模板包](SEQUENCE_9_EVENT_PACK.md)。

黑市和季度拍卖至少要有浏览、上架、购买、出售、拍卖开放和交易反馈。普通浏览/交易不强制弹阻塞卡；有真实选择的接触或后果才进入卡片。遵循CORE_LOOP的固定价格、固定槽位、验证后全局开放边界，不新增商品级来源/资格校验或动态NPC竞价。挂牌时长、手续费、商品池与固定槽位内容仍需制作；市场外的材料追索事件不因此自动解锁。

## 6. 事件抽取与多样性验收

- **条件正确**：不同序列、知识、职业、资产、污染和关系不会看到越权卡；不可见卡不以“隐藏按钮”泄漏标题或结局。
- **序列隔离**：每张阻塞事件只属于普通人或一个精确序列；晋升后旧层事件不再新抽取，未完成长期因果只能取消、结算为纪事或转换成当前序列的新事件定义。
- **同序列途径覆盖**：一个序列模板可以服务多条途径，但每条已发布途径必须拥有独立变体；至少改变切入、选择/目标和持续后果/扮演证据，纯换名或通用数值加成不算覆盖。
- **隐藏无泄漏**：未匹配特殊选项及其条件、数量、能力名和后果引用均不进入公开投影；满足条件后才出现，不展示“本来还有别的选项”。
- **重复控制**：同一 `diversityGroup` 有冷却和衰减；连续低价值重复行动不能无限刷同一张卡；连环阶段不重复生成。
- **因果连续**：上一张卡的 `nextRefs`、payload、线索和 NPC 状态可在重启后继续；参与者死亡/失效会按声明中断、替代或进入分支，绝不继续引用无效角色。
- **结果可重放**：同一事件实例、选项和随机流得到同一结果；重复点击返回同一 receipt。
- **信息安全**：RAG 只能提供来源候选和收据；模型不能生成新的事实、难度、选项后果或事件实例 ID。
- **玩家可读**：主舞台一次只突出一张阻塞卡；周脉冲的全部可知更新均可读，可以按来源折叠但不能截断丢失；卡片的每个选项都能追溯到一个解析入口和结果。
- **内容完整**：每个真实卡片通过 schema lint、来源检查、选项可达性、后果覆盖和人工原著/题材审查。

## 8. 事件调度与内容匹配细化候选 V1（2026-09-13）

本节是用户授权助手继续设计后形成的候选。EW已确认规则不变；新增具体权重、冷却和编排细节尚未经过试玩或用户整包审核。世界对象怎样产生机会、如何结算冲突见 [世界推理与事件因果](WORLD_SIMULATION.md)。

### 8.1 一张卡为何来到玩家面前

先区分“必须兑现的因果”和“可以抽取的情境”，不能把两者一起随机竞争。

| 入口 | 处理方式 | 可否被普通密度控制压下 |
|---|---|---|
| 当前选择的即时危险、战后后果、晋升结果 | 在该事件的结果链兑现 | 不可 |
| 已到期承诺/连环阶段、已明确购买或主动接触的结果 | 重验依赖后进入待办 | 不可 |
| 四行动产生的可选情境 | 合格候选抽取至多一张 | 可以降低抽取概率 |
| 世界新增可调查机会 | 留作计划事件/已知线索，满足入口再抽取 | 可以 |
| 不需要玩家选择的世界结果 | 纪事，不伪装阻塞卡 | 不计阻塞卡抽取位 |

普通人1—2张、非凡者2—3张是体验目标，不是删除必达事件的上限。链阶段与风险卡也计入玩家实际阅读负担，但不占独立卡抽取位；本周必达内容已经很多时减少新的随机卡，不阻止必达内容兑现。不能先把全部候选实例化，再靠“待办必须清空”逼玩家读完。

候选实例化前始终重验：精确序列、当前途径变体、当前行动/目标、人物阶段、地点、知识、资产、未结因果、冷却、唯一性。先筛选后抽取；不允许抽到无效内容后偷偷放宽条件。

### 8.2 试玩起始参数，不是正式平衡

普通人每次合格行动的基础随机卡概率取0.5；非凡者取0.75。无合格卡时概率为0。当前周已生成的阻塞卡达到目标下沿后，随机卡概率乘0.5；达到目标上沿后乘0.2。普通人下沿/上沿为1/2，非凡者为2/3；必达卡不乘这些系数。

未进入过当前实例的纯结果页、战斗动画和“继续”不另算一张卡。链的不同阶段分别计数；同一阶段多段对白不重复计数。周脉冲中间日期产生的卡归本次结束周，脉冲完成后产生的新周待办归新周，恢复存档不改计数归属。

连续两周无阻塞卡且存在合格内容时，下一次合格随机入口的概率暂取1；已有必达卡则结束事件荒状态。它只能使用确实合格的内容，不生成晋升材料、不恢复已结束案件、不越序列，也不保证每周必须弹卡。一次有效主要行动失败于“没有合格事件”仍保留基础行动反馈。

成为非凡者后，普通随机入口先在可用大类中按非凡相关70、生活社会30抽类，再类内抽卡。只一类可用时用该类；必达后果不为凑比例而换内容。高位仍可有生活关系事件，但必须是当前位格版本，不是换标题的低序列跑腿。后续试玩观察实际全部卡片的比例，而不把70/30抽取参数当成实际达标证据。

类内候选初始权重取1；玩家当前调查目标直接关联者乘3，当前有效成长线索相关者乘2，同一`diversityGroup`最近4周已出现者乘0.25。可同时满足，最终在合法候选中归一化。隐秘线索不能因权重加成变成玩家已知目标。

默认重复控制候选：同一可复用规则变体冷却4周、同一情境组冷却1周；唯一案件终身不再生成；链阶段按自身时间安排，不套普通冷却。内容确实需要重复时必须写出新的对象/处境及收益边界，不能靠更换文案重置冷却。重新加载、切换叙事变体和同日迁居均不重置历史。

上述参数只作为首个切片的起点。必达链过长应修剪内容或安排跨周间隔，而不是给玩家添加跳过代价或硬卡上限。

### 8.3 选项、日常被动与成本

处理次序固定为：确定当前事实和基础选项 → 读取本途径合法能力 → 匹配机会槽 → 自动应用允许的无额外成本日常效果 → 投影已解锁的特殊选择 → 玩家选择后结算。

- 被动可改善已声明的信息、预警、检定或后果保护，不要求玩家先转一个日常技能盘，也不插“是否发动能力”弹窗。
- 需要额外灵性、物品、暴露或污染代价的用法必须是玩家主动选择的事件路线，公开可知成本；不能在后台当被动免费替玩家决定。
- 基础选择仍以2项、关键阶段3项为可读性目标；匹配成功的特殊选择可以追加，不因基础数量目标被裁掉。若多个能力完全指向同一个结果路线，合并为一项并显示实际生效来源；结果不同就保留不同选项，不让后台任意挑一个。
- 未匹配特殊选项完全不发送到界面，包括文字、锁图标、空位、计数及条件。能力条件满足但尚未满足该隐藏路线的资源/知识条件时，也不提前显示它。
- 选项已经可见后，成本与普通判定依据应可解释；不能通过预览数字跳动泄露未获知敌人身份或秘密。未知危险用已设计的风险提示，秘密后续节点不能反向修改当前公开检定概率。
- 基础路线至少保留一条当前可提交的拒绝、退出、求援或承担后果路线；无钱/无材料不能把玩家卡在所有选项都禁用的弹层中。终局/强制后果可以只有承认结果，不伪造逃脱选择。
- 触发事件已经消耗一次主要行动时，同一事件内选择不再扣一次 AP。金钱、物品等按选择扣；确需另一次主要行动的后续任务安排为未来可主动调查的线索，不在 AP 为0的阻塞卡内索取第二次 AP。
- 选择时才支付该选择成本；打开卡、预览、被动匹配和失败重试不扣。合法尝试本身收费且失败不退的规则必须在对应选择中明确，不由通用事件系统猜测。
- 扮演/掌握度来自已经完成且符合本能力、本序列要求的行为证据。相同实例只能兑现一次；重复同一已解决矛盾不产生新证据。事件不能替代尚未设计的途径成长量表。

### 8.4 跨周、晋升与迁居

未生成的计划事件可以有明确截止后果；已经打开的卡不会因现实等待超时。读卡期间日期不推进。取消事件必须保留已付的真实成本与已发生事实，是否退款由原交易/事件规则决定，不一概回滚。

晋升或迁居后，对计划和待办逐张重验。正在结算的晋升事件先完成即时后果；首次晋升序列0后直接结清终局链，不再开放普通序列0周循环。

旧案件转为高序列版本时保留原案件因果 ID 和已兑现结果，但使用新的事件定义与当前序列变体，不再发一次旧阶段奖励。无高序列接续版本时，只能兑现已经声明的世界后果或取消未承诺的机会，不能临时把同一锅炉房敌人乘血量。关键晋升必需链在制作时必须提供接续/替代入口，不能用取消掩盖成长死路。

迁居只取消真实失去接触条件的本地机会；书信、远方承诺、追索和已知关系不会被城市切换清零。返回原城重新校验当前事实，不恢复旧世界快照。

### 8.5 序列9—0的事件问题尺度

以下是内容选题方向，不是新授予的能力或每个序列强制发生的剧情。每一层仍需独立模板和逐途径变体；相邻序列可使用相近题材，但必须以可使用能力、解决对象和持续后果形成实际差别。

| 精确层 | 玩家主要处理的矛盾 | 不采用的复用方式 |
|---|---|---|
| 普通人 | 生计、可信证据、关系、接触神秘的选择 | 自动得知非凡解释 |
| 9 | 隐藏在生活中的局部非凡危险，初次践行途径身份 | 给全部途径同一“使用能力”选项 |
| 8 | 新能力改变调查/处置路线，开始面对后续责任 | 只提高序列9检定难度 |
| 7 | 多方秘密与材料竞争，能力使用产生可追索影响 | 只有换皮日常差事 |
| 6 | 跨关系/机构的连续局面，已有能力组合改变结果 | 拿没掌握的高阶权柄当万能解 |
| 5 | 较大范围的因果、势力交涉与晋升准备取舍 | 强制加入固定组织 |
| 4 | 位格转折后的地区影响、非人代价与责任 | 继续为几枚零钱跑同一案件 |
| 3 | 多地点或长期后果、仪式条件与重要关系的维系 | 每周随机宇宙恐怖 |
| 2 | 与本途径高位能力相符的广域问题、重要人物与世界分歧 | 强行给所有途径相同治理工作 |
| 1 | 独有终局准备、争夺与不可逆代价 | 人为用大量普通卡拖延晋升 |
| 0 | 成神事件即时后果、关键因果收束和本局评价 | 成神后恢复日常抽卡周循环 |

高位仍可以探望旧友，但矛盾应是身份变化、能力影响、关系维系或既有因果的当前后果；不要求每次都拯救世界，也不让旧友变成按玩家序列自动升级的敌人。

### 8.6 每份途径变体的实际写法

一个模板只规定冲突骨架与结果轴。每条变体另写：当前精确序列；独立进入理由；角色实际具备的稳定能力 ID；作用对象；自动观察/保护；预写隐藏路线；可知成本；不能解决的问题；实际结果差异；扮演证据；下阶段因果。

例如同为序列9的首弧，既有占卜家、观众、猎人三份候选分别读取原有规则卡，不能仅用“调查加成”代替各自机制。其它19条已有途径稿不等于已经完成本弧三阶段变体；需要逐项接回真实能力和选择。某模板只适合其中几条可以明确限定覆盖，其余途径由同层其他模板提供内容，不强行把22条塞进每一件事。

生产按三个数字分别记录：模板数、真正可玩的途径规则变体数、审核文案数。一个规则变体加8份措辞仍只是一份玩法，不能据此声称事件数量增加8倍。

## 9. 下一批内容制作与设计完成边界

当前完成的是事件/世界的系统候选，非117张卡或全部22条成长弧成品。推荐制作顺序：

1. 用已有首弧补齐事件机会 → 实际选择 → 世界后果 → 下次可见机会的闭环，不再新造一条验证主线；
2. 将首弧其它19条方向草图逐条转为真实序列9变体，不能因途径稿到齐自动解除内容缺口；
3. 按精确序列扩展事件模板，每层同时覆盖调查、关系、成长资源、风险与后果，而不是只写晋升仪式；
4. 补22条四阶段弧及无需正式入会的资源路径；按实际内容链接检查能否持续成长，不用随机保底凭空送资源；
5. 最后批量生产审核文案，缺文案用固定回退，缺规则则不作为正式卡发布。

本次不锁定新模型、生成框架、硬件规格或外部服务，也不引入地图、即时寻路、组织经营或第二套任务系统。下一步整体设计查漏需明确区分：尚有玩法决策、已有设计待制作、已经制作待试玩。
