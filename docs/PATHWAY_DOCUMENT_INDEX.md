## 制作顺序

每条途径按以下顺序制作：

1. 核验序列名称、位格方向和原著边界；
2. 完成序列 9—0 的基础量化、配速和战斗盘；
3. 补齐战斗能力与日常效果；
4. 设计真正需要的特殊机制与特殊盘；
5. 补齐材料、配方、调配、仪式和内容入口；
6. 设计阶段用代表性算例与规则复核；有实现后针对变化做必要校验和真实游玩，不因文档改动跑全量测试；
7. 根据结果调整，并让该序列内容包进入真实可玩范围。

可以用明确标记的 fixture 开发通用引擎，但不能把候选值或 fixture 当作已完成途径。

## 一条途径何时算“完整设计候选”

完整候选需覆盖以下四层，并满足最后一项分层边界：

1. 基础与内容层：序列名册、新增能力、继承边界、成长弧、扮演证据和晋升内容入口；
2. 日常事件层：每个序列的事件被动、隐藏选项、主动硬成本边界和掌握度节点；
3. 战斗机制层：能力盘身份、目标/范围/AOE、特殊状态或特殊盘，以及不能绕过的胜负与生存结算；
4. 量化配速层：接入当前`COMBAT-V3`候选的基础战势、核心权重、A/E、盘型、六槽权重和次数盘，并列出该途径需要检查的代表性组合；旧V2表不能直接当当前胜负公式。
5. 分层边界：日常事件盘与战斗盘必须分别定义；战斗只读取开战状态/快照并在轮盘内闭环，不能依赖临时案件答案、长期预言、世界规律或其它事件叙事对象。

现有22条途径量化展开表只是第四层的底稿，不会单独把一条途径算作完成；反过来，只有能力与剧情描述、没有转盘配速和数值接线，也不算完成。

## 内容完成度

- 已确认：已有明确设计结论；
- 基准已确认：只确认基准或示例，不能外推整条途径；
- 候选或待定：仍需设计、验证或玩家确认；
- 待原著核验：原著边界尚未核验完；
- 历史记录：只用于追溯，不继续追加设计；
- 尚未实现：文档存在但代码还没有实现。

## 22途径统一审核（2026-09-07）

后续更新：题1—36均已回答，第31题在解释后确认A，不为神秘再现统一设置每场额度。以下保留审核时的问题与建议，不覆盖新确认；最新答案见`COMBAT_DESIGN_QUESTIONS.md`，规则见共用战斗与各主题文档，具体剩余工作见`DESIGN_PROGRESS.md`。尤其普通AOE现为固定总预算，多人小轮、保命转盘、死神指挥方向、回退/重启不设旧硬限次等不再是尚未选择的方向。

### 结论与范围

22条均已有序列9—0设计骨架，可以进入统一规则收尾，不需要重做22条。五条已确认整包保持确认状态；其余17条仍是候选。**本次文档审核完成，但不能宣布全途径通过、数值平衡完成或可以不加判断地照稿实现。**

本轮审核了22条的战斗机制、普通数值接线、独立实体与生存接口、日常能力入口和位格锚卡/晋升衔接；重点检查跨途径矛盾，并做一个两段触发概率算例。没有逐条重跑既有算例，没有进行完整原著来源复核、全组合模拟、产品测试或试玩。二手原著转录和分任务自报检查不能升级为本轮验证结论。审阅方法采用rpg的派生状态/结算检查与dialogue-systems的条件、分支和后果检查，没有引入额外资源或治理体系。

保留的设计方向：事件卡轻量承载内容；日常能力由行动进入的事件被动匹配；不合格特殊选项完全隐藏；按精确序列与途径身份分事件池；22途径不共用一套内容；独立身体保持独立轮盘；行动点耗尽推进一周；越高序列晋升越慢，不以五小时限制倒推晋升；组织由事件选择；GMZZ只参考RAG。

### 实现这些机制前应统一的共用问题

以下是审核发现及建议，不是新玩法确认。不影响这些问题的内容设计可以继续。

1. **能力执行顺序没有闭合，多身体胜负也没有闭合。** [战斗流程](COMBAT_ROULETTE.md)写了双方分别抽次数、双方转完再判胜负，但未确定交替行动的粒度、追加次数插入位置、零剩余次数时的触发和新实体入场时间。错误的连续窃取、门的开门保护、白塔的预提交预见都依赖此顺序。多人问题更实质：门对被囚者100%不代表对另一名敌人100%；观众正文却写操纵一名目标后“当前战斗按胜利结束”；倒吊人牺牲又能保证盟友下一回合成功。必须写清单目标对抗、整方胜负、各身体败者后果及共同身份死亡的关系，不能实现者任选。建议先画一轮具体多人战的执行顺序，把强制胜负的作用范围与相互冲突一起确定；不新增先手盘，不削掉三身体。

2. **快照失效与主动改盘混用。** [战斗规则第70行](COMBAT_ROULETTE.md)已明确回合内临时失效保留扇区、执行预写结果；[量化第1870行](PATHWAY_QUANTITATIVE_DESIGN.md)却泛称不可用即移除再归一。新稿也分别采用空转、同槽普通动作和立即移除。建议分清：回合生成时排除不可用项；回合中自然失效执行该能力已写的结果；窃取、剥夺、洞悉等明确改盘能力按其特殊效果更新。是否允许某能力回退普通动作要写在该能力，不要统一偷换为重抽。**黑皇帝保留快照并非越权，这项旧误判已撤回。**

3. **死亡链与“打不中但仍判死”的反例需要补齐。** [公共死亡规则](COMBAT_ROULETTE.md)已允许特殊能力提前进入死亡分支。黑皇帝湮灭本身不是违规则；实际空缺是它与替死、复归、重启、死神终点的顺序，以及多个机制失败后能否继续尝试。普通败者盘基础权重、受伤再败增量及高序列生存参数也未定。另一个需要明确排除的反例：纯物理攻击者对灵化怨魂，攻击全部不合法，但双方仍有基础战势；若仍按普通输赢给怨魂抽物理死亡，就绕过了免疫。建议后果读取本轮真实可致伤来源/场景后果，区分战术落败、被封锁和可致死攻击。不得把不同稿中的后果fixture误认成多套正式死亡表。

4. **AOE预算与特殊对抗的默认口径分叉。** 母亲/黄昏巨人等使用2人总140%、3人165%、4人以上180%；命运之轮/黑皇帝等普通群体贡献采用固定总预算分摊。相同能力预算在三目标时因此可能相差65%，不是文案区别。AOE数量盘也有等权、指数衰减和分档概率。对抗公式则分别按序列差或P差、不同掌握系数、不同无防护默认值计算。建议统一普通AOE默认预算、特殊对抗数值单位和复制能力读取哪一方公式；真正不同的能力再明确例外。白塔知识主导、门的100%等已有身份不能被一条通用公式抹平；不同公式本身不自动等于错误。

5. **灵性尚未设计，不能拿候选消耗或暗藏限次宣布平衡。** 错误分身的`4n²`是待确认值，门的回答明确没有战斗灵性设计；其他稿大量标未定。命运之轮连续重启100→80→60→40→20→0，数学上意味着同遭遇最多五次成功恢复，虽称“稳定性”仍是实际成功次数上限。它不是已确认规则。建议先确定战斗是否消耗灵性、如何显示和不足时发生什么，再检查维护/召唤/复归；不要给每条途径添加专属能量条。对已确认的黑暗复归，应读“第三次及以后继续同档”，不能误读成只许复活三次。

6. **入口概率不等于完整机制的出现率。** 暴君序列4原始H盘预备8%、主次攻合计55%，次数1—6权重10/17/24/24/17/8。无掌握度重加权、无干涉、基准独立抽取下，单回合至少一次准备为24.47%，但“先准备、后攻击”完成率只有13.57%；前者不能证明灾难场配速适宜。计算仅跟踪未准备、已准备、已激活三状态，按次数分布加权，不是平衡模拟。隐者现场再现、猎人两段能力也应看完整链路。建议之后只检查代表性的完成轮数、空转体验和多实体总盘数，不为此次文档审核跑全量测试。完美者“合并相同动画”的提议与公共“每次完整转盘、不合并同类结果”冲突；当前仍应执行快速逐次播放。

7. **高序列晋升的时间与世界承载尚未定。** 完美者稿提出文明周期，被缚者稿列百年封存，黑皇帝涉及多年仪式，死神序列4锚卡直接安排六十年轮回。这里首先需要核实具体来源和适用条件，本轮不能认证这些原著说法；若采用，就要交代起始日期、人物寿命、组织演变与未结事件。不能刚晋升4就无前提触发六十年到期，也不能把百年偷偷改成几次休息。建议另做统一的“长期仪式/时间跨度”设计取舍，并区分已有古老物件、真实等待和时间跃迁。当前不强制组织归属不等于不能存在教团/国家类仪式关系，但必须通过事件成立，而非选择途径后自动加入。

### 日常事件与成长：已具备什么，还缺什么

- 已具备途径身份、四类日常行动的能力入口和序列9—0锚卡骨架；新稿没有整体退回“序列0仍做序列9案件”。战斗与日常分层方向成立。锚卡只是身份示例，不能代表大量可持续游玩的事件库已经完成。
- 下一轮事件设计应按**精确序列适用范围＋主题事件族＋途径能力匹配**生成候选。共享的是适合共用的情境模板，不是22途径所有阶段共用正文；高阶继承低阶能力仍可解决高阶情境，不等于重新投放低阶任务。
- 每个重点事件补普通路线、隐藏路线条件、主动执行代价、能力被动提示、结果与后续。条件不满足时不显示灰色选项或锁头提示。能力揭示事实与使用能力改变事实必须分开，不能让小模型临时创造秘密、奖励或数值。
- 晋升要检查“尚在旧序列的玩家能否完成前置”，不能要求先有晋升后能力；序列0新能力掌握度0也要能结清即时终局。高级掌握度可服务高位NPC或明确剧情，但不能为了用到500节点暗加序列0长期周常。
- 原著人物交互、关系与组织议程、材料来源、仪式链、长期形态恢复、各地域高序列事件密度仍需接入世界设计。来源未核和配方未填是内容待补，不是允许AI自由补齐的区域，也不是暂停所有通用功能的理由。

### 建议的收尾顺序

1. 集中确定一轮战斗的执行顺序、多人胜负、死亡/复归链和普通AOE口径；先解决机制互相说不通的地方。
2. 玩家复审观众的明确歧义、死神的核心手感、命运之轮的重启限制，以及长期仪式的世界时间选择；原著事实先核验，不把查资料的工作反问给玩家。
3. 按已决定的方向修正文档，只对相关机制做少量算例；不重做22条、不批量改写已确认整包。
4. 进入事件卡与世界推理设计，随后全游戏查漏，再拆可玩纵向切片到独立开发任务。主对话仍只做设计和审核；Luna max做常规实现，Astra high做复杂实现。本报告不是新门禁或另一份状态账本。
