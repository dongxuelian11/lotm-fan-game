# 整体设计缺口检查

2026-10-09更新：这是9月13日查漏历史，不是当前全部待办。生活12题已答、20人格/10出身/55职业条件等已有试玩候选，四类首弧连续性现见FIRST_EVENT_ARC_DESIGN第16节。当前可交付范围、剩余八类路线与验收以PLAYABLE_SLICE_PLAN为准；该方案待整体确认，不宣称所有旧缺口已消失。

2026-09-13｜主对话设计审核。仅审核、列出建议，不替用户确认新玩法，不修改产品实现。

## 结论

游戏主干已经成立：普通人起步、四行动耗尽推进周、事件驱动成长、22途径9—0、转盘战斗、死亡/成神结算、有限世界推理、离线存档与可选文本模型。无需再增加一个大型系统，也无需重做22途径机制设计。

但目前还不能把“全部设计完成”交给实现对话。主要缺口有三类：普通人基础数值与生活闭环未填齐；成长/物品/治疗等系统连接处仍缺具体规则；大量正式事件、资源渠道和人物内容尚未制作。另有旧文档矛盾会直接造成不同实现。

可以准备有限切片，不能承诺完整9—0周目已经可施工。下面“影响首切片”指采用正式内容的普通人一周或第一调查弧；工程fixture可以验证技术，但不算填补正式设计。

## 1. 审核范围与方法

沿角色创建 → 普通生活 → 接触非凡 → 晋升与能力 → 战斗/治疗 → 世界反馈 → 终局与存档检查。读取总览、相关主题与首弧的具体规则，核对最新战斗回答、事件/世界候选与既有成长架构；用awesome-gamedev `rpg`的跨系统连接思路检查，不引入其通用XP、传统任务列表或装备槽默认玩法。

这是系统层文档交叉审核，不是所有22途径每一项能力的重新逐字原著核验，也不是源码功能审计。没有重新跑模拟、产品测试、浏览器或桌面验证。下述“未找到完整规则”限定于当前活动设计入口与主题检索；旧归档、临时代码和fixture不能替代正式设计。

分类：**规则缺口**＝同一输入还不能唯一确定怎样玩；**内容缺口**＝结构已定、具体卡片/表项/来源未齐；**体验待验证**＝已有候选，需要试玩而非继续猜数字；**旧稿冲突**＝已有结论尚未同步，不应重问用户。

## 3. 应先消除的旧稿冲突

### 3.1 首弧伤势表与保命流程仍是旧版——首战前必须同步

`FIRST_EVENT_ARC_DESIGN.md`“追击战斗的首弧专用败者后果盘”（约310—321行）仍写无伤60/35/5、一层45/40/15、两层及以上25/40/35，并说“每次再败严格上升”“保命按全局优先级”。两层以上固定35%本身也不满足每次上升。

最新 `COMBAT_ROULETTE.md` 开头确认段采用65/30/5、带伤再败每次向死亡移10；死亡与合法保命共同抽取，不预排保命优先级。旧首弧专用表是早期候选，没有据此绕开后来共用确认的依据。建议直接按最新确认同步首弧，具体场景例外必须另有实际来源，不重问已答机制。本次仅记录，未改首弧玩法。

### 3.2 工作收益与周收入可能重复——普通周循环前必须确定提交点

`CORE_LOOP.md`“经济和产业”明确工作结算职业与产业、每来源每周最多一次；“周循环”第5步又要求周末结算职业/产业收入，且产业称被动收益。若实现各读一段，可能双领；若一概只工作发钱，则产业是否无工作也产生收益又不明确。

建议先区分“工作取得工资资格”“产业周期产生收益”“实际入账时间”，每来源每周最多一次不能丢。助手可以给最小候选和0/1/2次工作三组账单；不能把选择某一解释冒充用户已定。

### 3.3 黑市是否允许动态限制/竞价——市场前统一，首弧不必等

`CORE_LOOP.md`末段明确联系人验证后永久全局开放、不做商品级资格/来源校验、不做动态NPC竞价。`EVENT_CARD_SYSTEM.md`第5.4节却仍把赃物风险、NPC竞争和竞价规则列为待设计；总览另有渠道/稀缺限制的一般描述。

应区分已开放黑市的固定商品交易与市场外的材料来源事件，不把一般叙事风险偷偷加回固定市场。建议保留当前具体边界，清理过期“待设计竞价”；如要改变，由玩家另作决定，不以查漏为由扩张市场。

### 3.4 创角摘要究竟只读还是能选学历——创角前统一

`UI_IMPLEMENTATION_PLAN.md`第3节与 `CHARACTER_AND_PROGRESSION.md`开头说摘要只读；`V1_CHARACTER_CREATION_SPEC.md`第12—15、28行和 `CORE_LOOP.md`却允许在摘要选择一个条件替代学历。

同一原型不能同时照办。推荐把可选学历及其代价放到前面的出身/职业上下文，摘要只展示已选结果，保持六步；这是推荐，尚未替用户确认具体交互位置。

### 3.5 人格轻量约束与旧情境影响表述不一致

`CHARACTER_AND_PROGRESSION.md`第18行只允许±1核心能力及最多一个可见情境标签，不能额外改数值、成本或行动；`V1_CHARACTER_CREATION_SPEC.md`第59行仍说特质影响检定、代价、NPC反应与可见选项。

需区分由±1属性自然影响检定、标签影响既定事件资格，与再次叠加额外成本修正。先按轻量边界起草20张卡，不自动加人格专属数值系统。

### 3.6 晋升节奏与过期完成状态

`PATHWAY_GAMEPLAY_ARCHITECTURE.md`第80行、`CHARACTER_AND_PROGRESSION.md`第58行的“各序列总体节奏相近”与后面的递减晋升决定不一致。以最新“越高总体越慢、不设现实小时目标”修正文案即可，不重新投票。

`COMBAT_ROULETTE.md`第247/255行仍把伤势健康损失列待定，但第86行已确认轻伤10%/重伤30%。这不是数字空缺，真正空缺是战后治疗与风险清除条件。首弧“其它19条被途径未设计阻塞”、开发流程“等待并行收稿”等也已过时：途径候选已到齐，事件变体仍待接入；不能再开启相同收稿任务。

## 4. 上轮事件/世界候选仍需补的连接问题

不是重做系统，而是给候选补几个边界算例：

- **周中事件与周末经济**：`WORLD_SIMULATION.md`允许周脉冲在真实到期点暂停选择；需要和收入/债务统一次序，确保不会周末先破产再追溯周中收款，也不能恢复时再发AP。
- **AP中途改变**：既有能力/伤势/职业/生活档位可修正AP，但“额度变化立即生效还是下周生效”“已耗尽后治疗或晋升能否取消待执行周脉冲”尚缺共同规则。尤其多秘偶代理增加AP，不能反复召回/召入刷周预算。
- **必须追索与拒绝后果**：关键材料有至少一条可追踪路线是已定方向；玩家主动毁掉唯一来源或拒绝所有代价后，不能同时承诺无限保证。先为实际材料链列作者设计的替代渠道与明确失败原因，不设计凭空送材料的万能保底。
- **信息预览**：事件要求不泄露隐藏选项和秘密；战斗可公开未知能力扇区占比。两者边界要在进入战斗时明确，不把战斗完整盘信息提前发给日常事件预览。
- **失效后果不能无限延期**：世界冲突无规则时保留争持是候选回退，不是正式重大事件的结局。关键人物死亡/关键仪式条件破坏，需要实际终止/改道内容，不能仅用“下周再试”维持假进展。

这些问题可由助手先设计窄候选；只有确实改变玩法取舍时集中请玩家审核，不需要现在重新发整套世界访谈。

## 5. 推荐补齐顺序

### 第一包：普通人可连续生活数周

先补当前首切片真正需要的：20张人格卡、出身/职业/学历最低完整表、工作入账与周费用顺序、四行动起始数值、AP修正时点、无钱降档/承担后果、休养与伤势治疗。生活费与已定属性形状复用现表，不全部从零设计。

完成标准是纸面能算通：角色确认后工作/学习/调查/休养，行动耗尽结算一次周费用；无钱不会弹出全灰卡，受伤后能知道怎样真正治好。该包可先由助手起草候选再集中审核；不是先造完整经济经营模拟器。

### 第二包：首弧正式内容接线

同步首弧新战斗后果；补可追击敌人的普通人/序列9实际盘与逃脱结算；复核归零分支的透支下限和结束路径；给相关人物/组织补足实际阶段和结果。只接首弧需用的物品最小规则，不等12件封印物。

### 第三包：占卜家序列9的非凡闭环

接触 → 配方/材料来源 → 调配/首次服用 → 能力在事件被动生效/战斗使用 → 伤势恢复 → 扮演/消化反馈。已有能力包和三个事件变体可复用，但要填真实获取与成长证据，不把十张锚卡当成完整成长弧。

### 后续扩展

逐精确序列和途径扩展内容；补市场/封印物、复杂同行与高位时间跃迁；制作终局评价内容；最后以实际试玩检验事件密度、晋升减速和多行动者战斗阅读负担。模型增强与音乐素材可以按切片需要接入，不作为核心离线玩法的前置。

## 6. 不应重复做的事

- 不重选引擎、不重新收22途径设计稿、不恢复固定现实游玩时长。
- 不把“有候选但未试玩”全都改报“玩法没设计”。
- 不以首版22途径范围要求先制作完所有卡才验证第一个切片；也不能用fixture宣称完整首版。
- 不把现有架构/存档方向重新变成一轮审批；不开治理任务、不计算哈希、不为了本文跑全量测试。
- 不在本轮直接改码或创建实现对话。本审核后的最有价值下一步是第一包基础生活与恢复设计，同时按既定答案修正旧稿冲突。
