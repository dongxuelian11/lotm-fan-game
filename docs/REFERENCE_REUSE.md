# 参考项目边界

参考项目只提供有限、明确的启发，不决定本游戏的架构、玩法或工作流程。

## 《汴京梦华》

只参考：

- 少量行动后时间推进、世界继续演化的节奏；
- 人物卷宗、紧凑时间日志、行动区和事件卡的信息结构；
- 事件池、事件链、冷却、重复衰减和生涯记录的设计思想。
- 到期连环事件在周期结算中优先于普通随机事件、一次只呈现一个选择弹层、处理后立即写入时间日志的节拍；
- 跨阶段保存参与者、阶段号、触发时间和必要载荷，并在参与者失效时重新校验的连续性思想；
- 调查信息优先组织为“人物怎么说 / 有什么可核 / 必须查明什么”，生成内容只作待证材料、本地规则才产生事实的边界。

不复制：

- 代码、文案、素材、宋代题材内容与全局脚本结构；
- localStorage 存档实现、可执行事件函数、动态 `innerHTML` 和直接 `Math.random()`；
- 官阶、科举、派系、地图与产品规则。

落到本游戏时，参考游戏的“每月2次行动”不照搬，而是转译为已确认的每周动态行动基准3、最低1；“月度脉冲”转译为周脉冲；长篇事件正文转译为一屏内的证据化事件卡；全局随机转译为动作级可记录随机流。借鉴的是玩家节拍和信息结构，不是参数或代码。

其根目录缺少足够清晰的许可边界，因此默认按 `REFERENCE_ONLY` 处理。

## gmzz / Mist Chronicle

gmzz 现在只有一个参考范围：RAG。

允许研究并重新实现：

- 候选文本检索；
- 来源 ID、manifest/hash 和检索回执；
- 玩家可见知识过滤与泄漏防线；
- 检索预算、失败停机和固定文本回退；
- 构建期内容审查与运行时表现文本的职责分离。

不再从 gmzz 参考或迁入：

- UI、地图、组织经营、自由文本任务卡与游戏节奏；
- world kernel、分层记忆领域模型、NPC/组织/项目 schema；
- Electron、IPC、SQLite、存档、事务回执、安装器或项目治理；
- `private/` 语料、原文、生成索引、seed、凭据、用户数据、数据库和构建产物。

本项目即使独立选择 Electron、SQLite、公开状态投影或幂等事务，也必须根据自身需求设计，不能再以 gmzz 为来源或默认模板。

## 原著与同人边界

角色、途径、序列、魔药、组织、地点与历史事实需要逐项原著核验；代码许可不授予原著正文、图片、音乐或发行权。仓库不收录原著全文、私人知识库或来源不明素材。

## 结论

《汴京梦华》提供玩家节奏与信息结构参考；gmzz 只提供 RAG 工程参考；本游戏的代码、数据、玩法与内容均在当前仓库独立设计和实现。
