# 原著、知识投影与 RAG 边界

## 原著权威顺序

1. 《诡秘之主》第一部合法取得的原作正文。
2. 作者发布的设定、问答、创作谈和正式访谈。
3. 官方出版物或官方衍生资料中明确标注的设定。
4. 带章节/问答索引的社区资料，仅用于定位和交叉检查。
5. 游戏改编推论，必须标记为 `GAME_ADAPTATION`，不能冒充原著事实。

《宿命之环》的补充规则不能无标记地倒灌成第一部同期角色已知信息。当前工作区没有合法原作全文语料，正式能力和神秘学规则写入前仍需逐条复核。

## 世界与玩家信息

- 世界从原作同期已核验事实起步；在玩家未改变关键条件时沿基线发展，但不是不可改写的录播主线。玩家通过已审核事件造成的可追溯后果可以改变人物、组织和后续事件，原著人物也可以受伤或死亡。
- 原著关键人物必须使用手工设计的稳定身份、状态、互动和事件卡。人物死亡、失去资格或改变归属后，相关事件与组织议程必须重验、取消或进入已审核分支，不能继续引用失效角色。
- 其他角色可以具名，但只保留玩法真正需要的轻量状态；姓名来自已审核内容或确定性名字池。运行时模型不能凭一句叙事临场创造新角色身份、人物生死或组织决定。
- 世界后台可以保存完整真相；玩家投影受角色知识、组织权限、序列、调查证据和污染风险限制。
- `知识`数值表示学习、理解和分析能力，不等于已经获得某个配方、真名、尊名、仪式或秘密。
- 知识记录至少需要来源、时间有效区间、获取方式、可信度/清晰度、权限、剧透层级和污染风险。
- 占卜是启示而不是真相按钮；成功仍可能有误读、遗漏、反占卜、位阶干扰或危险第三方响应。
- 封印物的成功发动和副作用分开结算；强力效果不意味着负面效果消失。
- 恐怖来自未知、有限认知和必须作出的选择；不能用无因果随机发疯或血腥反转代替克苏鲁感。

## RAG 是否可用

gmzz 只在这里提供“检索候选＋来源回执＋泄漏评估”的 RAG 工程参考；不复制其私有语料、用户数据、生成 seed、凭据、SQLite 存档或其他系统。RAG 只负责找候选文本和出处，不负责替游戏决定：

- 角色已经知道什么；
- 某个配方/真名/组织是否可见；
- 行动难度、胜负或后果；
- 原著事实和游戏原创是否冲突。

知识库应至少分开：世界真实、角色已知、玩家可见、来源章节、时间、组织权限、污染风险、剧透层级和 `GAME_ADAPTATION` 标记。检索结果必须附结构化来源回执，记录来源、版本、哈希和命中范围。

## 小模型职责

小模型适合做候选检索、摘要、终局档案润色和有来源文本的表达，不适合做权威规则裁决。确定性规则必须先完成：事实、参与者、人物生死、数值、条件、难度、资源、效果和终局标题由引擎决定；模型输出只能通过结构化合同、白名单渲染和校验后进入玩家界面。

模型不可访问秘密世界状态、未授权原文或超出角色知识范围的 RAG 内容。检索、提示、模型原文和私有上下文不进入 Renderer 的公开投影。

### 产品运行依赖

核心玩法、规则、正式事件和存档必须完全离线可运行；本地 RAG/小模型只作为可选增强层。模型缺失、超时、校验失败或硬件不足时，必须回退到已审核固定文本，不能改变规则结果，也不能把联网服务当作完成游戏的必要依赖。具体模型、运行框架、硬件预算、语料来源、在线更新和部署方式仍待后续设计。

### 检索架构

- `A_OFFLINE_LEXICAL_BASELINE_OPTIONAL_LOCAL_VECTOR_RERANKER`：确定性词法检索是离线必备基线；可选本地向量小模型与可选本地重排；叙事生成模型与检索层分离。
- 任一增强层缺失、超时、校验失败或硬件不足时，回退到已审核固定文本。检索层不拥有规则、世界状态、玩家知识或存档提交权。
- 本决定仍不锁定具体模型、框架、硬件、语料、在线更新、隐私或部署脚本。

本项目独立设计世界事实、观察、角色知识与玩家公开投影：Renderer 只接收已确认或传闻/推测的公开信息，暂时不可见事实完全省略。gmzz 的 `app/memory/**`、世界模型和主体 schema 不进入本项目；只参考其 RAG 来源 ID、有界检索与泄漏评估思路。RAG 检索权与角色世界内知识权继续分离：模型能检索到的原著资料不等于角色已经知道。

标准22条神之途径的序列9—0都在首版设计范围内；可以按统一记录批量整理候选，但不能把批量生成当作原著核验。每项途径能力、材料、配方、仪式和封印物效果都必须附来源等级与“待核验/已确认/游戏适配”状态，未核验内容不得进入正式玩家池。

项目建立封印物全量目录，但第一版仅12件拥有完整游戏规格。全量目录可以保存来源、别名、时代/组织和核验状态等索引元数据；没有可核来源或正文授权的条目不得补写效果、真名、仪式或秘密。RAG 只能返回带来源的候选，不能替代内容核验或规则引擎。

## 事件卡生成边界

事件卡采用“精确序列模板 + 途径独立内容变体 + 原著RAG锚点 + 小模型叙事变体”。模板只复用同一序列的问题规模、参与者槽、冲突骨架和结果轴；每条途径的成品变体必须另行固定事件切入、能力路线、选择、难度、成本、扮演证据、奖励、惩罚、知识与后果。RAG只返回有来源且经过权限/剧透过滤的原著人物、地点、组织、途径、时间线和禁写项，不能生成或补齐路径变体与隐藏选项。所有场景可以使用构建期审核通过的叙事变体，但同一规则内容的事实与结算必须完全相同；每个可复用变体以1份固定回退文本加8份审核措辞为生产基准。运行时本地AI只可依据引擎已经确定且玩家可知的事实生成即时描述、传闻措辞和NPC对白，不得新增规则或存档变化。

原著时间线是周目基线，玩家造成的有效因果可以形成分支，但分支必须由已审核内容和状态结算驱动，不能由模型即兴裁决。选项前公开精确玩法难度、当前概率和主要可预见后果，但这些数字不得成为泄漏角色未知原著事实、幕后身份或秘密的侧信道。模型不可用、超时或校验失败时必须回退已审核固定文本，不能重掷规则结果；通过校验的即时文本与事件实例一并保存，保证重读一致。
