# 原著、知识投影与 RAG 边界

`STATUS=RESEARCHED_BOUNDARY / SOURCE=LOTM_CANON_GAMEPLAY_AUDIT.md,RAG_FEASIBILITY`

## 原著权威顺序

1. 《诡秘之主》第一部合法取得的原作正文。
2. 作者发布的设定、问答、创作谈和正式访谈。
3. 官方出版物或官方衍生资料中明确标注的设定。
4. 带章节/问答索引的社区资料，仅用于定位和交叉检查。
5. 游戏改编推论，必须标记为 `GAME_ADAPTATION`，不能冒充原著事实。

《宿命之环》的补充规则不能无标记地倒灌成第一部同期角色已知信息。当前工作区没有合法原作全文语料，正式能力和神秘学规则写入前仍需逐条复核。

## 世界与玩家信息

- 世界后台可以保存完整真相；玩家投影受角色知识、组织权限、序列、调查证据和污染风险限制。
- `知识`数值表示学习、理解和分析能力，不等于已经获得某个配方、真名、尊名、仪式或秘密。
- 知识记录至少需要来源、时间有效区间、获取方式、可信度/清晰度、权限、剧透层级和污染风险。
- 占卜是启示而不是真相按钮；成功仍可能有误读、遗漏、反占卜、位阶干扰或危险第三方响应。
- 封印物的成功发动和副作用分开结算；强力效果不意味着负面效果消失。
- 恐怖来自未知、有限认知和必须作出的选择；不能用无因果随机发疯或血腥反转代替克苏鲁感。

## RAG 是否可用

可以复用 gmzz 已审计的“检索候选＋来源回执＋泄漏评估”工程思路，但不能复制其私有语料、用户数据、生成 seed、凭据或 SQLite 存档。RAG 只负责找候选文本和出处，不负责替游戏决定：

- 角色已经知道什么；
- 某个配方/真名/组织是否可见；
- 行动难度、胜负或后果；
- 原著事实和游戏原创是否冲突。

知识库应至少分开：世界真实、角色已知、玩家可见、来源章节、时间、组织权限、污染风险、剧透层级和 `GAME_ADAPTATION` 标记。检索结果必须附结构化来源回执，记录来源、版本、哈希和命中范围。

## 小模型职责

小模型适合做候选检索、摘要、终局档案润色和有来源文本的表达，不适合做权威规则裁决。确定性规则必须先完成：事实、数值、条件、难度、资源、效果和终局标题由引擎决定；模型输出只能通过结构化合同、白名单渲染和校验后进入玩家界面。

模型不可访问秘密世界状态、未授权原文或超出角色知识范围的 RAG 内容。检索、提示、模型原文和私有上下文不进入 Renderer 的公开投影。

`D-WORLDFEEDBACK3=A` 采用与 gmzz 分层记忆同类但重新建模的知识边界：Main 保存世界事实、观察、知识授权和主体信念；Renderer 只接收已确认或传闻/推测的公开投影，暂时不可见事实完全省略。gmzz 的 `app/memory/**` 不是可零修改搬入的独立包；只抽取其受众过滤、来源 ID、幂等交付回执与有界检索原则，并按本项目 schema 重写。RAG 检索权与角色世界内知识权继续分离：模型能检索到的原著资料不等于角色已经知道。

## 事件卡生成边界（已锁定）

事件卡采用“固定规则模板 + 原著 RAG 锚点 + 小模型叙事变体”。模板/引擎固定触发条件、选项、难度、成本、奖励、惩罚、知识与后果；RAG 只返回有来源且经过权限/剧透过滤的原著人物、地点、组织、途径、时间线和禁写项；模型只改写标题、描述和有限氛围细节。按已锁定的 `D-EVENT10=A`，变体在作者/构建期生成并审核，运行时按确定性随机流选已审核文本；不能让模型临场新增事实、数值、选项、后果或秘密。`D-EVENT11=A` 进一步限定事件卡以受原著约束的原创旁线为主，不改写原作主线。`D-EVENT15=B` 要求向玩家公开精确玩法难度、当前概率和主要可预见后果，但这些数字不得成为泄漏角色未知原著事实、幕后身份或秘密的侧信道。生成失败时必须回退固定文本，不能重掷规则结果。

## 许可证与语料

代码许可、原作 IP、原文、私有知识库和发行权是不同问题。没有明确授权前，不把网络抓取全文、社区整理包或第三方图片导入项目，不因 gmzz 的 MIT 代码许可推定获得《诡秘之主》内容许可。
