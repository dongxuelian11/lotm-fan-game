# UI 与交互设计

本文件把已确定玩法映射为可施工的屏幕与交互。界面以《汴京梦华》的紧凑行动节奏和日志结构为参考，但视觉、代码与具体布局由本项目独立实现。

2026-10-10（UTC+8）视觉决定：用户要求回到第一版，已选择[复古蚀刻插画＋清爽卷宗界面](VISUAL_STYLE_PROPOSAL.md)。有效参考为主图“简洁顶栏”版本2和事件卡“字体修订”版本1；两次CK3试稿均已否定，仅作归档。保留大字号黑体正文、左上角无大游戏名。首版简化三栏布局、整体方案与实施授权仍待确认；静态样稿不覆盖本文件已确定交互与规则，也不代表产品实现。

## 1. 体验原则

- 玩家始终知道当前日期、剩余行动、关键状态和最近发生了什么。
- 普通操作尽量在常驻周舞台完成，不为每个动作切换页面。
- 真正需要选择的事件必须获得完整注意力；通知类消息不能伪装成选择。
- 每次状态变化显示来源和前后值，避免“数值莫名变化”。
- 神秘信息按已确认、传闻/推测、暂不可见分层，不用 UI 泄露秘密。
- 页面优先服务游玩和阅读，不堆叠设计状态、内部 ID、测试证据或开发术语。
- 事件卡、案件卷宗与世界日志承担主要内容导航，不建立庞大的传统任务列表；克制的内心叙述可受人格特质影响，但不替玩家选行动。

## 2. 主界面

桌面版使用流体三栏周工作台：

- 左栏：人物卷宗、四项核心能力、健康/精神/灵性/污染、扮演与成长摘要；
- 中栏：按时间追加的世界推演与事件结果日志，提供少量分类筛选；
- 右栏：背包/能力切换，以及当前上下文需要的物品或能力详情；
- 顶栏：日期、金钱、剩余行动与最紧急状态；
- 底部：工作、学习、调查、休养四个固定行动，以及最新紧凑回执。

1280×720 是最低桌面尺寸，1600×900 是设计基准。左右栏设合理上下限，宽屏优先增加中央日志空间；主页面不产生横向溢出。

视觉方向为已选复古蚀刻＋清爽卷宗：低饱和排线人物/场景、深墨色背景、浅旧纸信息面与少量暗红；琥珀仅用于必要状态。常驻左上角不放大游戏名，顶栏优先地点与完整游戏日期。正文、选项、状态数字与辅助说明统一清晰黑体，宋体仅用于标题；1600×900基准正文20px、选项20–22px，缩放重排而不裁字，完整规格见视觉提案第2节。避免大面积装饰、过度发光与参考项目视觉复制。

## 3. 角色创建

六步流程使用同一舞台连续完成：

1. 身份、出生地、预设肖像、受控外貌标签与可选简短描述；
2. 出身；
3. 当前职业；
4. 两个特质与一个缺陷；
5. 只读开局摘要；
6. 确认。

预设肖像保持8款纯外观选择，并入第1步；创角内可返回重选且保留其他输入，不增加步骤或数值效果。本批按用户要求采用年轻成年人、非黑人外观，不做年老外观；仅约束玩家预设，不改写NPC或18—45岁创角年龄字段。现有8款蚀刻像仅部分符合要求，不符合项待替换，尚未导入或完成逐图审阅。

每一步都常驻显示四项核心能力及来源明细。出身、职业、学历、特质和缺陷在点击前即可预览有符号变化；点击后更新总值。职业页只显示当前出身的 `DIRECT` 与满足说明的 `CONDITIONAL` 职业，禁止项不作为可点击卡片混入。

第 5 步集中显示身份、出身、职业、学历、人格、初始资金、能力变化、关系/风险和特殊开局线索；不允许在摘要页暗中追加新选择。第 6 步才创建周目。

## 4. 行动交互

四个主要行动直接提交，不出现二次确认对话框。按钮在提交前展示最关键成本、目标和可能触发的判定；不可用时说明具体原因。

一次行动的可见反馈顺序：

1. 按钮进入处理中，防止重复提交；
2. 行动成本与普通结果写入紧凑回执；
3. 若需要玩家选择，打开阻塞事件卡；
4. 事件选择后显示结果与后果；
5. 中栏追加轻量世界回应；
6. 若行动点耗尽，先逐张清空本批阻塞事件，再自动进入完整周脉冲、推进一周并显示周摘要；不出现额外结束周确认。

工作、学习、调查、休养都可能触发事件卡并形成扮演证据。回执只在事件结算确认契合度、理解、风险和新意后显示扮演进度变化；按钮点击本身不得先显示虚假的成长奖励。

学习与调查允许先在抽屉中选择主题、材料、目标或线索，然后通过同一个主要行动提交。它们不是第五、第六个固定行动。

## 5. 普通判定

普通判定结果组件显示：

- 使用的核心能力和基础值；
- 每个修正的来源；
- d100 掷骰；
- 四档解决质量；
- 与质量分开的有序后果；
- 金钱、状态、知识、线索或世界变化的前后值。

玩家不需要看到隐藏事件条件、秘密 NPC 状态或未揭示难度来源。

## 6. 事件卡

需要玩家选择的事件使用页面级居中阻塞弹层：

- 背景设为不可交互并锁定焦点；
- 一次只显示一张卡；
- 标准卡使用两个有意义选项，特殊卡可声明第三项；
- 选项在可知范围内展示硬成本和风险；
- 提交后不能通过关闭弹层撤销已支付的行动成本；
- 完成后焦点回到触发位置或下一合理目标。

其他已经生成且需要选择的事件进入待处理入口，并必须逐张全部解决后才能提交下一个主要行动；若行动点已经耗尽，清空后自动推进一周。界面一次仍只打开一张。处理待办事件不额外消耗行动点，但硬资源成本照常。计划事件留在内部状态，不泄露；不可操作内容进入纪事。

事件由领域层先从当前精确序列内容包选取，再装载当前途径的独立成品变体，最后匹配该变体内部的隐藏选项。界面只能渲染收到的最终事件和选项，不为其它序列、其它途径或未匹配路线保留空位、灰色按钮、锁图标、问号、选项计数或“需要某能力”的提示。日常被动可以自动改变信息、判定、后果或令一个预写隐藏选项出现，但不增加额外的“是否发动”交互。

事件卡在视觉上标明其来源于共享世界、途径成长弧、人物/组织弧或连环案，但不展示内部阶段键。普通人阶段以日常内容为主；成为非凡者后，整体候选体验向约70%的非凡相关事件转移。原著关键人物使用专属头像/姓名位、关系阶段和近期原因（素材未完成时使用合法占位视觉），轻量具名角色只展示当前场景必要信息。人物死亡或资格失效后，界面只能展示已提交的取消、替代或分支结果，不能继续出现失效对话。

## 7. 战斗

战斗在周舞台上打开全屏遮罩，不提供常驻“战斗”按钮。它是多回合转盘，而不是一次总胜负动画。界面按顺序呈现：

1. 参战者、环境和已知风险；
2. 玩家为自己选择战术姿态，并为可用消耗品做本回合预授权；队友只接受宽泛姿态；
3. 各行动者独立结算次数盘；
4. 逐次展示能力盘，命中 AOE 时再展示命中数量盘与合法目标盘；能力和具体目标不由玩家点选；
5. 双方行动结束后展示当前回合胜负盘；
6. 败者进入轻伤、重伤、死亡分支、逃脱/俘虏与特殊机制后果盘；
7. 若遭遇未结束，带着伤势和已消耗资源进入下一回合；否则返回周舞台或进入死亡封存卷宗。

玩家必须能回看每回合的姿态、次数、能力、AOE数量、目标、胜负与败者后果。受伤后继续作战需明确显示“受伤模式”和当前累计死亡风险上升原因；再次败北或再次受伤会提高后续死亡分支权重。胜负盘只表示当前回合胜负，不能显示成直接决定整场死亡的单一轮盘。因果允许时，在回合边界显示风险明确的撤退或投降入口。

## 8. 市场、能力与档案

- 金钱同时显示镑、苏勒、便士，内部继续使用便士整数；
- 黑市与季度拍卖使用独立抽屉/页面，交易结果明确记录价格、来源和资源变化；
- 能力面板分开显示序列位格、扮演/消化与单项能力掌握度；
- 知识与线索详情显示玩家知道的来源，不显示私有 RAG 文本；
- 人物关系显示关系类型、定性态度与近期原因；每个组织显示一条综合关系阶段和一个当前可知议程。默认状态明确显示“未加入正式组织”，只有事件卡选择加入后才显示一个主要正式组织；途径页面不得暗示必须加入组织；
- 世界推演按时间顺序展示本次周脉冲中全部玩家可知的人物、组织和地区更新，可以滚动或按来源折叠，但不能用“只显示前几条”丢弃内容；
- 地点抽屉只列出已解锁且具有正式事件池的目的地；迁居作为情境行动显示行动消耗、旅费、到达日期与事件池切换，不增加地图或第五个固定行动按钮；
- 第一版不提供恋爱入口或恋爱关系分类；
- 周目死亡后进入只读终局卷宗，可查看角色经历、关键选择和死亡因果。

## 9. 屏幕状态

```text
TITLE
  ├─ RUN_SLOTS → NEW_GAME → CHARACTER_CREATE → WEEK_DASHBOARD
  ├─ RUN_SLOTS → CONTINUE → WEEK_DASHBOARD
  └─ ARCHIVE → RUN_ARCHIVE

WEEK_DASHBOARD
  ├─ ACTION_DRAWER → RESOLUTION → RECEIPT
  ├─ EVENT_OVERLAY → EVENT_RESULT
  ├─ COMBAT_OVERLAY → CONSEQUENCE / DEATH_ARCHIVE
  ├─ MARKET / AUCTION
  └─ WEEK_PULSE → WEEK_SUMMARY → WEEK_DASHBOARD
```

浏览器开发版没有正式继续游戏能力时，标题页必须明确标示“开发试玩，刷新重置”。

正式桌面版提供多个周目槽位；每个槽位只显示一个滚动自动存档及系统恢复用的最近备份，不提供事件前/战斗前手动回滚。槽位卡显示角色、日期、当前序列、生命周期与最近提交时间；死亡槽位直接进入只读卷宗。自动保存只在行动、事件、交易、晋升或完整战斗回合已经提交后更新，轮盘动画中不得产生可利用的中间存档。

## 10. 可访问性与手感

- 所有操作可用键盘完成，焦点顺序与视觉顺序一致；
- 弹层打开时焦点进入弹层，关闭后恢复；
- 不只依赖颜色表达成功、危险、污染或禁用；
- 主要正文保持可读字号与对比度；
- 支持减少动画偏好；
- 轮盘动画只表现已确定结果，不能让动画时序改变随机结果；
- 行动提交、数值变化、事件出现和周推进使用短而一致的声音/动效反馈，后续由 `game-feel` 与 `audio-design` 调整。

## 11. 实现边界

React Renderer 只发送类型化意图并显示公开状态。浏览器内存适配器与 Electron/SQLite 适配器共用领域规则。详细责任见 [技术架构](TECHNICAL_ARCHITECTURE.md)。
