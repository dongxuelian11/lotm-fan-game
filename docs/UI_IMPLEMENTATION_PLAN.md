## 1. 审计结论转成产品原则

《汴京梦华》最值得保留的是节奏：玩家完成少量行动，时间推进，世界产生回应，再给玩家下一组选择。它的双栏卷宗、右侧日志、底部行动区和事件弹层可以作为信息架构参考；宋代文案、官阶、全局脚本和 localStorage 存档不进入本项目。

gmzz 最值得吸收的是边界而不是产品外壳：Renderer 只编辑意图和显示公开投影，Main/SQLite 才能验证和提交；回合有明确状态、回执、重放和失败停机；叠层弹窗有焦点管理；RAG/模型输出不直接成为世界事实。地图优先、组织经营、自由文本拆任务卡不作为本项目默认玩法。

因此第一版采用“个人卷宗驱动的周行动游戏”：永久保留角色状态和本周行动入口，事件卡、调查、判定、战斗和结算以居中的面板/弹层展开，避免切走玩家对当前周次的上下文。事件卡不是日志装饰，而是行动结果、调查推进、黑市/拍卖后果和世界脉冲的统一玩家决策入口。

## 2. 工程底座（R0 已冻结）

### 2.1 技术边界

第一版使用 React + TypeScript Renderer、Electron Main、SQLite 权威存档和纯 TypeScript 领域内核。领域规则不依赖 React；Renderer 通过窄 IPC 发送类型化意图，只接收经过受众投影的 `PublicState`。共享合同和精确 API 由主任务逐轮冻结，详见 [架构合同](ARCHITECTURE_CONTRACT.md)。

建议沿用 gmzz 中可独立抽取的小边界：CSP、运行目录校验、稳定存档 origin、manifest/hash/source-register、请求回执和 exactly-once 事务。`persistence-sqlite`、旧 save schema、gmzz 领域模型和 UI 不整块搬运；实现时先按本项目字段重新建表。

### 2.2 最小运行状态

```text
TITLE
  ├─ NEW_GAME → CREATE
  ├─ CONTINUE → WEEK_SUMMARY
  └─ ARCHIVE → READ_ONLY_ARCHIVE

CREATE → WEEK_SUMMARY → DASHBOARD
                    ↓        ↑
             ACTION_PREVIEW ─┘
                    ↓
       CHECK_RESOLUTION 或 COMBAT 或 EVENT_CARD
                    ↓
              ACTION_RESULT
                    ↓
        仍有行动？DASHBOARD：WEEK_SETTLEMENT
                                      ↓
                                WEEK_SUMMARY

DASHBOARD → MARKET_VIEW → LIST / BUY / SELL → TRADE_RESULT → DASHBOARD
DASHBOARD → QUARTERLY_AUCTION（每三个月可用时） → AUCTION_RESULT → DASHBOARD

任意行动/周脉冲 → EVENT_CARD（阻塞卡） → EVENT_RESULT → DASHBOARD 或下一张到期卡
未阻塞事件 → PENDING_EVENT_LIST（摘要/到期/连环进度，正式名称待定）

任意结算 → 触发玩家死亡 → TERMINAL_ARCHIVE
任意结算 → 满足非死亡终局 → ENDING_CHOICE（结束或继续）
```

每次状态迁移都有 `turnId`、规则/内容版本、随机流标识和 `PersistenceReceipt`。UI 可以显示“处理中/已提交/需要重试”，不能在 Renderer 自己补随机或重复结算。

## 3. 屏幕和布局

以下结构依据已锁定的 `D-UI1..3` 施工。桌面最低验收尺寸为 1280×720；窄屏改为抽屉堆叠，不出现页面级横向滚动。

### 3.1 标题与存档页

只有四个主要入口：继续游戏、新建游戏、历史封存、设置。继续游戏卡片显示角色名、当前周次、途径/序列、健康/精神/灵性和最后一次结算摘要；死亡周目显示锁定的“只读封存”，没有回档按钮。设置只放音量、文字速度、显示密度和本地模型开关，不混入玩法配置。

### 3.2 捏人页

保持已锁定的六步短流程，不做长表单：

1. 基础身份：姓名、性别、18—45 岁、鲁恩境内出生地、预设头像。
2. 出身：从10张整合出身卡中选择1张，按五层社会阶层分组且每层2张；实时说明阶层、家庭基线和社会环境。贫民组两张卡分别以“无依街巷长大”和“负债失业家庭”为核心，清楚区分弱家庭支持/街巷求生与家庭关系/债务义务；劳工组两张卡分别以“工厂工资家庭”和“雇主依附的服务家庭”为核心，清楚区分工业雇佣/工友网络/停工风险与接触较高阶层家庭环境/雇主依附/声誉义务，并明确这些是家庭背景而非当前职业；上流层至少展示贵族与非贵族精英各1张。
3. 当前职业：从12个长期身份入口中选择1个，显示收入、义务和机会倾向；每项按 `DIRECT`、`CONDITIONAL`、`FORBIDDEN` 显示兼容状态。条件项在确认前展示背景解释及明确代价、义务或家境变化并要求接受；禁止项不可确认且显示不泄密理由；具体120组状态与代价后续锁定。
4. 人格：恰好2个性格特质 + 另选1个真实缺陷，显示会改变的代价，不显示属性加点；少选或多选均不能进入下一步。
5. 自动摘要与专精：展示派生的体魄/感知/意志/知识、基础普通技能、关系和资源，并要求从背景过滤后的候选中选择恰好1项普通技能专精；摘要即时更新，未选或多选不能继续。
6. 确认：明确“普通人开局、没有魔药和序列能力”，确认后创建首个周次。

布局采用“左侧当前选择卡 + 右侧角色预览/后果摘要 + 底部上一步/下一步”。冲突校验在当前页就地显示；不把关系、秘密、家庭成员拆成额外配置页。

### 3.3 周仪表盘（核心屏）

```text
┌ 顶栏：周次/日期 │ 金钱 │ 健康 │ 精神 │ 灵性 │ 污染 │ 本周行动剩余 │ 设置 ┐
├ 人物卷宗(280px) ─┬──────── 当前周舞台(自适应) ────────────────┤
│ 头像/身份/职业    │ 周摘要：上周变化、当前焦点、可见线索             │
│ 途径/序列         │ 当前事件或调查上下文（没有事件时显示世界焦点）    │
│ 四项核心能力      │ 纪事摘要：只显示与玩家相关的 3—7 条              │
│ 能力与掌握度      │ 可展开“完整纪事”抽屉，不在主屏灌入数百条日志      │
│ 状态/污染/资源    │                                              │
│ 关系/物品/产业    │                                              │
└──────────────────┴─────────────────────────────────────────────┘
┌ 固定行动区：工作 │ 学习 │ 调查 │ 休养  + 情境行动徽标（有条件才出现） ┐
```

左栏是可折叠卷宗，不复制参考项目的官员名册；中心区优先显示“本周我需要做什么”和“上周世界怎么回应”。行动按钮点击后先打开预览，不立即扣资源。底部四个核心按钮永远位置稳定，情境按钮按序列、身份、地点、线索、关系、状态和事件插入第二排。

顶栏只放玩家需要持续监控的数值；能力详情、知识来源、污染诊断和产业明细放入卷宗抽屉，避免把所有系统堆在主屏。

### 3.4 行动预览与调查面板

点击工作/学习/调查/休养后，中心舞台变为预览卡：行动目的、已知硬成本、预计资源趋势、可能获得的知识/掌握度方向、不可提前公开的未知风险。玩家选择“执行”或“返回”，执行请求进入 Main 校验。

调查面板分三层：

- 上下文：地点/人物/线索/玩家已知知识，秘密内容不越过投影边界；
- 可执行项：调查、观察、交涉、跟踪、撤退等由内容条件生成的按钮；
- 结算区：普通情境走四档数值判定，只有真正进入战斗才切换战斗转盘。

结算后先显示“解决质量”（大成功/成功/失败/大失败），再按顺序列出真实的因果后果项、来源和变化前后值。大成功不强制等于收益，大失败不强制等于惩罚；界面不能用颜色先替玩家解释因果。

### 3.5 事件卡弹层与非阻塞事件容器（候选）

事件卡沿用参考项目“标题 + 情境描述 + 纵向选项”的低学习成本，但由结构化数据驱动。卡片打开前，Main 先持久化 `OPEN` 实例；玩家只能提交一个稳定 `choiceId`，重复点击返回同一回执，不重新抽卡。按照已锁定的 `D-EVENT4`，日常行动固定成本先提交，随后才打开该行动的阻塞卡；卡片不能通过返回撤销行动成本。

卡片从上到下固定为：

1. **上下文条**：周次、地点、人物/组织、事件类型和连环阶段标记；
2. **事实与规则预览**：玩家可见的正文和线索；选项公开精确硬成本、判定难度、当前成功概率和主要可预见后果；实时战斗胜率进入战斗界面后精确显示；
3. **选择区**：标准卡默认2个选项；连环/阈值卡只有定义声明例外时才有3个，显示意图、能力/物品需求和唯一主要入口 `NONE/CHECK/COMBAT/TRADE`；数值预览不得泄露角色未知事实；
4. **结果态**：解决质量、按顺序的实际后果、资源/知识/掌握度前后值、下一张卡的时间和来源。

非阻塞事件采用已锁定的最小待处理事件列表；此前的 `EventInbox` 只是候选俗称，正式实现名称可另行确定。列表放在周摘要/纪事抽屉，不成为第五个行动按钮，也不创建第二套行动系统；只有定义声明可操作且条件仍满足时才显示“处理”。`D-EVENT8` 已锁定处理不消耗周行动点，`D-EVENT9` 已锁定每张可延期卡带到期周并执行显式到期后果。`D-EVENT10=A` 已锁定内容变体在构建期生成并审核，`D-EVENT11=A` 已锁定原创旁线、原著约束、不改主线，`D-EVENT12..18` 已锁定候选池、配比、单卡解析、精确信息公开、重复控制、连环衔接和死亡入口。

事件卡与 `OverlayStack` 共用焦点圈、Escape 返回、背景 inert 和重复提交锁。所有标题、正文和按钮都以白名单文本节点渲染，RAG/模型输出不得直接进入 `innerHTML`；处理失败停留在原卡并允许重试。

### 3.6 战斗面板

战斗保持调查上下文，但用居中遮罩锁住背景操作。推荐采用单一顺序面板：

1. **战前快照**：双方序列/位格、核心能力、健康/精神/灵性、可用能力/装备/封印物，以及本轮使用的快照版本。
2. **次数盘**：双方分别展示由实时面板生成的非均匀次数分布，转出本轮次数；正常可行动角色最低 1 次。
3. **能力盘**：双方按各自次数逐次转动；展示项目、精确占比和主要权重来源。玩家不能战前删格子配牌；同一项目是否可重复、消耗或失效由条目声明。
4. **回合纪事**：按时间顺序显示命中、胜势有向增量、资源/状态变化和未知区命中，不一次弹出多个结果。
5. **胜负盘**：双方能力盘全部完成后才生成，只输出胜利/失败；不在这个盘判定生死。
6. **因果结算**：胜负后的伤势、逃脱、俘虏、污染、暴露、救援和战利品按来源结算。健康归零再进入独立生存盘，失败即死亡并转终局封存。

每一步都有“继续”而不是自动跳过，便于玩家理解诡秘世界的戏剧性；战斗失败后本次遭遇结束，界面只提供查看结果和回到周舞台，不提供同一战斗无限重开。

### 3.7 周结算与终局

最后一次行动提交后自动打开周结算遮罩，固定顺序显示：行动结果 → 职业/产业收入 → 生活费/债务 → 健康/精神/灵性/污染 → 知识与掌握度 → 扮演/魔药（存在时） → 世界脉冲与新事件。每项都显示变更前后值和来源；大量 NPC 世界变化默认折叠为摘要，可展开完整纪事。

死亡或玩家确认结束后进入只读生涯卷宗，使用已锁定的六类摘要：终局事实、身份/最高序列、能力成长、组织与关键关系、资产/道具/封印物、重大事件时间线；再显示结局称号和传记摘要，不显示统一总分。

### 3.8 经济、产业、黑市与季度拍卖

经济不是隐藏在后台的一行“可信度”，而是玩家需要准备和取舍的资源。顶栏显示可用现金；点击钱包打开经济抽屉，分为“现金、生活档位、债务、产业、交易记录”五个折叠区。内部统一保存便士，界面组合显示金镑/苏勒/便士（1 金镑 = 240 便士，1 苏勒 = 12 便士）。

**工作与产业**：工作预览明确列出职业工资和每项有效产业收益，周结算合并入账但逐项列明来源。产业卡显示名称、地点、类型、规模 1—5、状态、净周收益和可用的升级/事件入口；规模倍率使用已定的 `1 / 2 / 4 / 7 / 11`。产业不是抽象加成图，必须能点开查看资产和风险。

**生活与债务**：经济抽屉显示赤贫、贫困、普通、体面、奢华五档生活水平，以及当前周自动费用、固定应还额和现金缺口。贝克兰德基准个人周费按已定的 `30 / 120 / 300 / 600 / 6000` 便士显示，实际值再乘城区系数。资金不足、搬迁、催款、违约和产业风险以事件弹层呈现；不静默透支、不自动降档。

**黑市**：黑市不是第五个固定核心行动，而是从经济抽屉、调查线索或情境按钮进入的交易界面。默认分为四个页签：

1. **浏览**：按类别、稀有度、来源风险筛选当前可见商品；只显示玩家有资格知道的内容。
2. **上架**：选择背包内物品、数量和期望价，显示挂牌费用/风险预览；提交后获得可追踪的挂牌记录。
3. **购买**：显示价格、渠道、真伪/风险提示和确认前硬成本；购买结果可能进入普通事件，而不是强行保证获得。
4. **出售**：选择已持有物品并显示预计成交/风险；实际收款和后果写入交易结果。

交易页不自行决定金钱、物品或污染变化，所有变化由 Main 生成交易结果并写入经济账。黑市具体挂牌时长、手续费、赃物风险、NPC 竞争和竞价规则仍是后置经济 Grill；本页只实现已锁定的查看/上架/购买/出售能力。

**季度拍卖**：每三个月在周摘要和经济抽屉出现“拍卖会”入口；未到周期时显示下一次日期和“尚未开放”，不占用固定行动按钮。拍卖页展示珍稀物品、已知来源、当前最高价/出价状态和玩家可承担的硬成本；竞价和拍卖后果沿用后置规则，第一版先保留可审计的拍卖记录和结果弹层。

### 3.9 知识、掌握度与扮演

卷宗增加“知识与成长”抽屉：知识属性 0—500 单独显示；每条非凡知识记录带来源、获得方式、玩家可见等级和是否可用于当前行动。学习行动预览必须说明“获得具体知识 + 可能增长知识属性”，但知识值不能直接替代配方、仪式、真名或秘密条目。

能力列表显示每项能力的掌握度 0—500、已解锁节点和已知消耗；学习、有效调查和战斗后的熟练度收益按既定随机分配规则进入结算，不提供玩家直接挑选能力的按钮。扮演进度、魔药消化度和能力掌握度使用三条不同进度条；符合原则的行动才显示扮演收益，调查在同等条件下收益更高。魔药、晋升和序列内容未完成时，成长抽屉只显示已确认字段，不制造假选项。

### 3.10 情境入口、社交与地图边界

不设置独立“拜访”按钮。人物互动、交涉和关系变化从调查、事件或满足条件的情境按钮出现，结算结果进入事件链和关系记录。第一版也不显示城市切换/地图按钮；贝克兰德是标准开局城市，地图版本再单独接入。

### 4.2 Main/领域合同

第一版先定义并测试以下纯数据合同，不让事件配置携带任意函数：

- `CharacterState`：身份、途径/序列、核心能力、状态、污染、能力掌握度、资产和公开关系。
- `WorldState`：周次、地点、公开局势、事件候选、NPC/组织公开投影。
- `ActionDefinition`：按钮来源、前置条件、硬成本、预览趋势、判定/战斗入口、后果引用。
- `EventCardDefinition/Instance`：事件类型、条件、权重/冷却、可见投影、选项、后续引用、实例状态和可重放随机流；定义不携带任意函数。
- `EventReceipt`：事件实例、choice、解决入口、后果序列、下一阶段/到期信息和持久化回执。
- `EconomyState`：便士现金、生活档位、债务、产业资产、周收益、挂牌和拍卖周期。
- `TradeIntent/TradeResult`：黑市查看、上架、购买、出售的意图、验证结果、物品/金钱变化和风险事件引用。
- `AuctionState`：季度周期、可见拍品、出价状态、结算回执和下一次开放时间。
- `ResolutionRequest/Result`：规则版本、难度、修正、骰面、四档质量、按顺序的 `ConsequenceItem[]`。
- `BattleRoundSnapshot`：双方实时面板快照、可触及项目、次数盘/能力盘配置、随机流游标。
- `RouletteConfig`：项目权重、掌握度曲线、当前修正、未知底噪/因果追加和归一化结果。
- `SettlementReport`：固定结算顺序、每项前后值、来源、下一周候选和终局标记。
- `KnowledgeProjection`：玩家可见知识 ID、来源等级、已知/未知边界和 RAG 收据 ID。
- `GrowthReport`：知识属性变化、随机掌握度收益、扮演进度、魔药消化进度及各自来源。
- `PersistenceReceipt`：`turnId`、attempt、事务版本、内容/规则版本、随机流收据、状态哈希。

Main 负责预检、随机流、规则计算、SQLite 事务和投影；Renderer 不能写 `CharacterState`，也不能接受未验证模型 JSON。所有结构化渲染使用白名单字段，不把模型文本直接插入 HTML。

## 5. 分片施工顺序

### Slice 0：壳、存档和确定性骨架

交付：Electron/React 壳、标题/存档占位页、OverlayStack、焦点与响应式布局、Main/SQLite 最小 schema、迁移、回执和 fixture 状态。先用固定假角色和假周次，不写具体途径能力。

验收：重启可恢复；重复提交只返回同一 receipt；随机流可重放；秘密字段不在公开投影；1280×720 和窄屏无页面溢出；上述自动测试状态在实际运行前保持 `NOT_RUN`。

### Slice 1：周仪表盘和四个核心行动

交付：顶栏、人物卷宗、周摘要、四个固定按钮、情境按钮插槽、行动预览、事件卡弹层/非阻塞事件容器（待定）、经济/产业抽屉、黑市查看/上架/购买/出售、季度拍卖入口、周脉冲和周结算。工作/学习/调查/休养先接最小 fixture 结果，收入、恢复、知识使用和事件结果回执接入已锁定规则。

验收：行动真实扣减动态行动力；末次行动自动进入周脉冲；工作同时结算职业工资和有效产业收益；黑市交易不绕过 Main 账本；每三个月生成拍卖入口；行动结果和周脉冲能生成一张可重放事件卡；同一时刻不出现两张阻塞卡；趋势预览不泄露未知副作用；周结算每项可追溯；事件而非状态标签承载经济/生活后果。

### Slice 2：普通判定和调查纵切

交付：调查上下文、证据/知识投影、统一 d100 四档判定、显式有序后果项、事件卡/非阻塞事件容器（待定）、线索/三阶段事件链最小内容包。加入普通人开局到第一次非凡线索的可重复 fixture。

验收：客观不可能先判定；成功率按已锁定差值公式；大成功/大失败与实际后果可独立；RAG 只能提供候选/来源收据，不能决定难度或事实。

### Slice 3：双阶段战斗转盘

交付：战前快照、次数盘、能力盘、回合纪事、胜负盘、生存盘和死亡分支；用三条首版途径各一个占位能力验证数据结构，不批量制作全序列内容。

验收：双方次数盘均完成后才进胜负盘；能力盘按实时面板但回合起始快照；权重非均匀且可解释；胜负盘只输出胜负；健康归零进入独立生存盘，玩家死亡转只读封存。

### Slice 4：结算、封存和可读性

交付：周结算、经济/交易账、季度拍卖记录、终局六类卷宗、完整纪事抽屉、摘要/展开策略、重启恢复和只读存档入口。

验收：工作、生活费、债务、产业和交易的变化均有来源；大量世界变更不阻塞主舞台；结局事实/称号由确定性规则生成；死亡存档不能回档继续；播放器可从标题页打开历史封存。

### Slice 5：内容管线和第一组真实能力

交付：内容 schema、版本/来源/校验、内容 lint、能力/事件卡/商品/产业/拍卖编辑模板；先用12张事件 fixture 卡和1条三阶段 fixture 链验证，再录入占卜家序列9的最小真实能力包，按序列逐组添加并做批量转盘模拟和原著人工复核。

验收：非法目标、缺失 `onZero`、越界权重、负价格、不可达事件选项和未登记扩展处理器拒绝载入；每项能力都有普通判定区块、战斗区块、消耗、掌握度节点和来源；每张事件卡都有触发/可见条件、至少两个有意义选项、解析入口、可追溯后果和来源；商品、挂牌和拍卖记录有来源/状态校验；未完成能力不伪装成完整途径。

## 7. 当前不锁定与下一批 Grill

事件卡结构、常驻周仪表盘、全屏遮罩战斗和视觉方向均已锁定。本节保留历史选项，不能据此重新打开决定。

### `D-UI1` 周舞台外壳

- **A（已选）**：一个永久周仪表盘，调查/判定/战斗/结算用居中弹层或右侧抽屉；保留周次上下文，开发量最低。
- **B**：标题、卷宗、调查、战斗、结算各自独立页面；层次清楚，但页面切换多、状态恢复和上下文成本高。

### `D-UI2` 战斗承载面

- **A（已选）**：在当前周仪表盘上打开全屏遮罩式战斗面板；玩家能看到进入战斗的调查背景，返回路径短。
- **B**：独立战斗页面；沉浸感更强，但需要额外保存/恢复周舞台和更多导航状态。

### `D-UI3` 视觉方向

- **A（已选）**：克制的“神秘学卷宗/工作台”——深墨色底、旧纸色信息卡、琥珀/暗红作为状态强调，细线和印记感，不复制 gmzz 或汴京梦华。
- **B**：偏明亮的纸张/档案馆——阅读压力低，但污染、危险和夜间神秘感较弱。
- **C**：中性工具界面——最快实现和测试，但题材辨识度最低。

`D-UI1=A`、`D-UI2=A`、`D-UI3=A` 已封板；具体色值、字体、动画时长和插画来源在实现视觉令牌与资产清单时继续受控确认。

### `D-EVENT3` 事件卡默认选项数量 — `LOCKED`

- **A（已选）**：标准卡固定2项；连环/阈值卡只有在定义中声明例外时可有3项，首版最易测试和保持选择重量。
- **B**：每张卡由作者在2—4项间自由决定，表达空间大但平衡与可达性检查更复杂。
- **C**：所有卡固定3项，结构统一但内容工作量和无意义选项风险最高。

### `D-EVENT4` 日常行动与事件卡的结算先后 — `LOCKED`

- **A（已选）**：确认日常行动后先提交固定行动成本，再弹出该行动的阻塞事件卡；返回不能撤销成本，最容易保证重放与账本一致。
- **B**：先弹卡，由选项决定是否/如何扣行动成本；选择感更强，但会增加取消、重复提交和恢复边界。
- **C**：行动先自动结算，事件卡只做被动事后通知；实现最简单，但卡片不能改变行动结果。

### `D-EVENT5` 哪些日常行动可以生成阻塞式事件卡 — `LOCKED`

- **A（已选）**：四个固定行动都可以在满足条件时生成一张阻塞卡；工作/学习/休养通常是短卡，调查/市场卡可进入判定、战斗或交易。
- **B**：只有调查、黑市/拍卖和阈值结果生成阻塞卡；工作、学习、休养只显示结果面板。
- **C**：每次固定行动都必须生成一张选择卡；反馈统一，但会显著增加打断和内容量。

### `D-EVENT6` 阻塞式事件卡能否暂存/跳过 — `LOCKED`

- **A（已选）**：阻塞卡必须当场作答；非阻塞事件可以延后，并进入 `D-EVENT7` 锁定的最小待处理事件列表。崩溃、死亡或条件失效时写明 `EXPIRED/CANCELLED` 原因。
- **B**：允许玩家把阻塞卡延后一周；自由度更高，但会产生待处理堆积和连环案顺序问题。
- **C**：允许直接跳过并执行定义好的默认后果；实现简单，但可能被用来规避风险。

### `D-EVENT7` 非阻塞事件的保留与展示方式 — `LOCKED`

- **A（已选）**：只做一个最小“待处理事件列表”，放在周摘要/纪事抽屉中；显示标题、来源、到期周和“阅读/处理”，不增加行动次数，也不是第五个按钮。
- **B**：不保留待处理列表；非阻塞事件只写入只读纪事摘要，之后不能处理。
- **C**：做完整事件收件箱，支持筛选、排序、批量处理和手动挑选待办；信息最全，但会变成第二套任务系统。

这题已锁定为 A；完整筛选、排序、批量处理和自由挑选不进入第一版。“收件箱”只作为历史俗称，正式实现名称待定。
