## 2. 工程形态

最终交付仍是本地单机 Electron 桌面应用，不改成网络游戏或网页发行。`D-TECH2` 只改变施工顺序：先在浏览器中把可玩内容和界面做稳，再套接桌面壳。

- 浏览器施工阶段：React + TypeScript + Vite Renderer 通过与正式版相同的公开意图/投影合同连接开发态内存审查运行时；该运行时调用同一套纯 TypeScript 领域规则和内容，刷新可重置，不提供正式存档。
- 桌面套壳阶段：把同一公开合同接到 preload、Electron Main 和 SQLite，恢复发送方校验、事务回执、重启恢复与桌面安全门禁。
- 前端工作流：负责 Renderer、响应式布局和浏览器实际交互；不在组件中复制规则。
- 后端工作流：浏览器阶段优先负责领域规则、判定/模拟、内容校验和测试；Main/preload/SQLite 只在轮次合同明确进入套壳阶段时扩展。
- 主任务：共享合同、浏览器审查适配边界、根配置、轮次合同、集成测试、接线、Git 和用户审查。
- 设计 Grill：只读调查并逐题采访用户，不编辑文件、不提交候选、不自行推进；用户回答由主任务固化。

详细依赖和信任边界见 `ARCHITECTURE_CONTRACT.md`。

## 3. 每轮固定状态机

1. 若本轮存在必须由用户决定的设计缺口，主任务先暂停主任务实施、前端与后端，派发设计 Grill 任务只进行提问；用户回答后由主任务写入台账/主题 MD、审计并提交，再冻结 `ROUND_ID`、合同版本、共享类型、写集、验收场景和停止条件。
2. 主任务对照 `docs/architecture/runtime.archify.json` 冻结 `ARCHITECTURE_BASELINE_SPEC_SHA256`、`ARCHITECTURE_CHANGE` 和 `ARCHITECTURE_STATUS`；拓扑变化必须先更新架构合同和图并通过 Archify 门禁，内部变化则记录 `ARCHITECTURE_CHANGE=NONE`。
3. 前端/后端从同一已知基线在独立分支/worktree 实现当前阶段写集；浏览器施工轮中，前端做真实交互，后端做同一领域规则与内容，不默认扩展 Main/SQLite；任何越界改动先报给主任务。
4. 两边分别提交原子变更和证据，状态到 `READY_FOR_INTEGRATION` 后停止。
5. 主任务重新读取源码与提交头，先检查合同和架构漂移，再按轮次声明的顺序接线；不直接相信任务摘要。
6. 主任务运行类型、规则、schema、契约、集成和构建门禁；浏览器施工轮另做真实浏览器审查，桌面套壳轮另做 Electron smoke 与 SQLite 重启恢复。任一门禁失败都不升级状态。
7. 主任务向用户展示本轮实际界面/流程、已知缺口和证据；浏览器通过只写浏览器阶段验收，不能自动升级桌面、存档、打包或发布；用户明确通过对应阶段后才写相应 `PLAYER_ACCEPTANCE=PASSED`。
8. 只有上一轮接线、架构一致性和用户审查关闭后，主任务才冻结下一轮合同。

`READY_FOR_INTEGRATION ≠ INTEGRATED ≠ PLAYER_ACCEPTED ≠ PACKAGED ≠ RELEASED`。

## 4. 分轮路线

### 施工阶段覆盖：浏览器优先、桌面壳后接

从R2纠正及后续玩法轮开始，默认先交付浏览器可玩审查版：真实领域规则、真实交互和当前轮内容经共享合同接线，但只使用开发态内存运行时。R1/R2已经取得的 Electron/SQLite 证据作为历史底座保留，不要求每个玩法小步都重新启动桌面壳。

当玩法、布局和主要流程获得玩家确认后，再进入桌面套壳门禁：接回 preload/Main/SQLite，验证幂等事务、重启恢复、Electron 安全边界、安装包和干净机器。浏览器证据与桌面证据分别记账。

### R0 — 开源与治理基线

主任务独占：本地 Git、MIT 代码许可证、NOTICE、README/贡献/安全说明、架构合同、写集、轮次账本和任务注册。公共 GitHub 远端与发布在实际建立前保持 `NOT_CONFIGURED/NOT_PUBLISHED`。

用户审查：开源边界、主计划、前后端权限和第一轮范围。

### R1 — 桌面壳与权威状态边界

`STATUS=PLAYER_ACCEPTED_HOLD / MASTER_GATE_SHA=14d17c60eb910137a270c645993d374ab74f5231`

- 前端：标题页、无存档态、周仪表盘空壳、中央叠层和 mock bridge；
- 后端：Main/preload 启动、SQLite 元数据/迁移、幂等回执、最小公开投影；
- 接线：真实 preload/IPC 替换 mock，验证启动、创建 fixture、重启恢复、重复提交不重复生效；

### R3 — 普通判定与事件卡纵切

- 前端：阻塞卡、最小待处理列表、精确难度/概率、后果和纪事；

### R5 — 战斗转盘与生存/终局

## 5. 轮次完成定义

每轮必须同时满足：

- 前端和后端各有锁定提交头、写集和测试回执；
- 浏览器施工轮必须接入真实领域规则而非静态页面 mock；桌面套壳轮必须接入真实 Main/SQLite，浏览器审查适配器不能冒充最终主路径；
- 自动门禁终态明确，失败/未运行如实记录；
- `PROJECT_STATE_LEDGER.md`、`ROUND_LEDGER.md` 和两个工作流状态一致；
- 轮次合同记录的架构 baseline hash 与当前冻结源一致，且不存在未处理的 `ARCHITECTURE_DRIFT`；
- 用户看过本轮实际体验并明确通过，或本轮保持 `AWAITING_PLAYER_REVIEW`；
- 不把下一轮的设计空缺静默塞进当前实现。
