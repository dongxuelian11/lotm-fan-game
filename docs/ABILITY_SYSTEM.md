# 能力系统与熟练度

第一版彻底移除独立普通技能、普通技能熟练度和普通技能成长节点。出身与职业直接提供加成；非凡能力继续使用0—500掌握度、五个节点和逐能力专属效果。

## 能力记录原则

- 一项原著能力只有一个扁平权威记录和一个界面条目；多种用法写在说明和专属规则里，不拆成互相独立的子技能。
- 同一能力共享名称、身份和掌握度，但分别保存普通情境判定参数与战斗转盘参数。
- 每项能力显式声明资源消耗：无消耗、固定灵性消耗或专属代价；已知成本在使用前显示。
- 每个能力最终都要由用户逐项确认实际效果，不能用通用“伤害/加成”模板替代原著差异。

## 22途径批量制作规则

首版可玩范围包括标准22条神之途径的序列9—0。能力可以按统一记录格式批量录入，但不能把批量录入误当成统一效果。

- 每项能力仍单独填写所属途径、序列、原著来源、普通用途、战斗权重、胜势贡献、掌握度曲线、资源/目标/持续和特殊效果。
- 通用字段无法忠实表达的能力才绑定版本化、可测试的受控特殊处理器；处理器不能绕过统一结算或直接修改存档。
- 22条途径可以批量生成“结构完整的候选记录”，但每一项效果都必须经过原著核验、用户确认和战斗模拟；未确认记录保持 `PENDING`，不能进入正式玩家内容。
- 运行时 RAG/小模型只能改写已经确定且玩家可知的描述、传闻或对白，不能生成能力规则、概率、胜负、奖励、惩罚或新的原著事实。

内容按途径依次完成：先逐序列完成掌握度、战斗转盘权重、非战斗效果和特殊处理器审查，再进入下一条途径；不能把制作顺序误写成具体能力已经完成。

每条途径必须先完成该途径序列9—0的数值、配速和战斗盘设计，才能把特殊机制形成完整候选。数值阶段至少覆盖该途径各序列的核心权重、基础战势、行动次数来源/范围、实时能力盘项目、盘面权重和胜势贡献；特殊机制不得反向替未确认的数值或战斗盘做决定。占卜家、错误、门、观众、猎人和死神现已形成完整设计候选，但仍待玩家总审、原作正文核验、联合模拟与实现。

具体能力以可独立运行的连贯内容包制作；每包包含数值表、极端案例和判定/转盘模拟，确认设计后进入正式玩家内容。首个实际内容包先完成占卜家序列9—0的能力记录，材料、魔药、仪式、事件和经济联动随后补入；这不等于完整玩家循环已经完成。

占卜家按一个序列一个连贯包推进，包内同时提供该序列全部能力的战斗/非战斗字段、原著证据、测试表和100/200/300/400/500五个掌握度节点候选；用户确认后才进入下一序列，未确认节点不得进入正式玩家内容。

确定性词法检索必须离线可用，可选本地向量小模型与可选本地重排，叙事生成与检索分离；增强层缺失、超时或校验失败时回退已审核固定文本。模型无权生成能力规则或修改存档。

战斗效果与非战斗用途可以分开设计和审查，两侧并行起草，最终必须合并回同一项正式能力记录；共享能力ID和版本，公共记录维护身份/版本，战斗侧维护战斗字段，非战斗侧维护非战斗字段。若字段冲突就标记为待解决并禁止发布，不能静默覆盖。两侧都通过审查后才发布为可玩能力，期间只保留内部草稿；分开审查不意味着两套能力或两套存档规则。

## 已固化的途径设计档案

途径内容现在统一收口到[途径设计固定入口与归档规则](PATHWAY_DOCUMENT_INDEX.md)：[基础序列](PATHWAY_BASE_DESIGN.md)记录名册与序列骨架，[量化与配速](PATHWAY_QUANTITATIVE_DESIGN.md)记录基础战势/行动次数/战斗盘，[战斗机制](PATHWAY_MECHANISMS.md)记录特殊机制，[日常技能效果](PATHWAY_DAILY_EFFECTS.md)记录非战斗能力字段。旧的愚者/观众文件仅为历史镜像，不代表运行时已经实现；数值、掌握度节点和跨途径平衡仍须按本文件的能力记录与审查门槛处理。压缩火球明确归入猎人途径，不属于愚者途径。

游戏适配来源标签只保留在资料库和内部审查记录，玩家界面使用世界内描述；每项适配能力必须保留来源标识或可复核定位、短摘要、适配差异、短引文、人工备注、置信度和审查状态，不复制大段原文。具体来源工具和文件格式仍待后续确定。

## 规则适用范围

普通能力使用统一数值判定；战斗转盘已有独立的次数盘、能力盘、胜负盘和胜负后因果后果流程。两者不互相套用。

## 能力内容应覆盖的字段

具体 schema 仍在底层阶段建立，但每个能力至少要能表达：

- 所属途径、序列、版本和原著来源；
- 普通情境的适用核心能力、前置、目标、判定参数和后果；
- 战斗中的基础权重、胜势贡献、可触及条件和命中效果；
- 灵性/特殊代价、目标范围、持续时间、冷却/充能、重复命中规则；
- 健康、精神、灵性、污染、暴露、知识、线索和事件等结果后果；
- 100／200／300／400／500五个熟练度节点的专属变化；
- 是否需要受控扩展处理器及其版本。

## 掌握度

掌握度是每项非凡能力独立的0—500整数，不是核心属性，也不是序列位格。所有新获得能力从0开始；主动能力在0仍可粗糙使用，被动基础效果立即生效，精细控制与高级运用需要成长。第一版不存在普通技能掌握度。

掌握度的通用作用只有“更会使用当前能力”：每项能力可自行规定控制精度、消耗、持续、风险、高级用法或战斗稳定性变化，但不得统一增加成功率或把熟练度换算成通用有效能力值。序列/位格决定能力本质和强度上限，500熟练度不能把低序列能力变成高序列能力。

所有能力共用五个节点100、200、300、400、500；节点位置统一，节点具体效果逐能力设计。没有新机制的节点也必须声明它强化了哪个既有效果。

## 掌握度来源与随机分配

- 完成有效学习：生成5点熟练度收益包。
- 调查/非战斗情境中发生有效能力运用并结算：生成8点。
- 完成一场有效战斗：生成25点，每场最多一次，与回合数、胜负和触发次数无关。
- 同一周没有收益包总数硬上限；重复同一低风险、无新代价/威胁/信息的刷取不产生收益。
- 每个收益包从角色已知的非凡能力中随机选一项，玩家不能指定，未实际使用的能力也可被抽中；第一版普通技能不进入候选池。
- 候选权重按掌握度分档：0—99为5，100—199为4，200—299为3，300—399为2，400—499为1，500为0并退出候选池。权重在收益生成时计算并持久化。
- 目标达到500时，超出部分直接作废，不转移，不把整笔收益重抽。例如490获得25，最终为500，剩余15作废。

## 数据驱动与特殊处理器

普通能力优先使用统一数据配置。只有通用字段无法忠实表达的特殊能力才绑定受控扩展处理器；处理器必须可测试、可版本追踪并参与模拟校准。

扩展处理器不能直接写存档、绕过胜负或任意改世界状态。普通能力处理器只能返回该能力的判定参数和结果后果，由统一数值判定处理；战斗处理器只能接入已经声明的转盘流程。所有随机必须由引擎提供的行动级可复现随机流产生，并记录流标识、取数顺序、结果和能力版本。

## 普通能力判定

非战斗能力直接使用统一的四档数值判定。能力记录声明适用的核心能力、难度/修正、前置、目标和可能后果；判定一次完成，结果按普通成功、大成功、普通失败或大失败进入能力或事件的具体结果数据。

第一版不建立独立的公共效果事务、能力级预检、逐项回滚或通用成本锁定系统。能力是否消耗灵性、改变状态、写入线索或触发事件，随该能力/事件的数据和统一判定结果处理；具体能力逐项设计时再填写。

## 战斗能力

战斗能力只进入已锁定的次数盘、能力盘、胜负盘和胜负后因果结算。能力的战斗权重、胜势贡献、命中效果、物品/封印物和特殊效果写在战斗能力参数中，不调用普通能力判定的事务规则。

## 能力设计顺序

先完成统一数值判定和最小能力记录，再按途径/序列逐项录入普通判定后果与战斗参数。每完成一套序列，跑批量转盘模拟并人工做原著审查；数值或能力效果若暴露底层缺口，就回到对应设计文档修正规则。

当前能力记录使用显式目标选择器，未声明特殊范围时默认单一目标；效果的持续与叠加字段遵守最小规则，不得在具体能力中自行增加全局机制。
