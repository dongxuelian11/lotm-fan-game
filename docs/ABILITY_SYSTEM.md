# 能力系统与熟练度

`STATUS=PARTIALLY_LOCKED / SOURCE=D-ABILITYSCHEMA1..5,D-ABILITYMASTERY1..15,D-ABILITYCONTENT1,D-ABILITYENGINE1..4,D-ABILITYRESOLUTION1,D-ABILITYEFFECTSCOPE1`

## 能力记录原则

- 一项原著能力只有一个扁平权威记录和一个界面条目；多种用法写在说明和专属规则里，不拆成互相独立的子技能。
- 同一能力共享名称、身份和掌握度，但分别保存普通情境判定参数与战斗转盘参数。
- 每项能力显式声明资源消耗：无消耗、固定灵性消耗或专属代价；已知成本在使用前显示。
- 每个能力最终都要由用户逐项确认实际效果，不能用通用“伤害/加成”模板替代原著差异。

## 规则适用范围

普通能力使用 `D-ABILITYRESOLUTION1` 的统一数值判定；战斗转盘已有独立的次数盘、能力盘、胜负盘和胜负后因果后果流程。两者不互相套用。

## 能力内容应覆盖的字段

具体 schema 仍在底层阶段建立，但每个能力至少要能表达：

- 所属途径、序列、版本和原著来源；
- 普通情境的适用核心能力、前置、目标、判定参数和后果；
- 战斗中的基础权重、胜势贡献、可触及条件和命中效果；
- 灵性/特殊代价、目标范围、持续时间、冷却/充能、重复命中规则；
- 健康、精神、灵性、污染、暴露、知识、线索和事件等结果后果；
- 100／200／300／400／500五个熟练度节点的专属变化；
- 是否需要受控扩展处理器及其版本。

## 掌握度

掌握度是每项技能和能力独立的0—500整数，不是核心属性，也不是序列位格。所有新获得能力从0开始；主动能力在0仍可粗糙使用，被动基础效果立即生效，精细控制与高级运用需要成长。

掌握度的通用作用只有“更会使用当前能力”：每项能力可自行规定控制精度、消耗、持续、风险、高级用法或战斗稳定性变化，但不得统一增加成功率或把熟练度换算成通用有效能力值。序列/位格决定能力本质和强度上限，500熟练度不能把低序列能力变成高序列能力。

所有能力共用五个节点100、200、300、400、500；节点位置统一，节点具体效果逐能力设计。没有新机制的节点也必须声明它强化了哪个既有效果。

## 掌握度来源与随机分配

- 完成有效学习：生成5点熟练度收益包。
- 调查/非战斗情境中发生有效能力运用并结算：生成8点。
- 完成一场有效战斗：生成25点，每场最多一次，与回合数、胜负和触发次数无关。
- 同一周没有收益包总数硬上限；重复同一低风险、无新代价/威胁/信息的刷取不产生收益。
- 每个收益包独立从角色已知的全部非凡能力和普通技能中随机选一项，玩家不能指定，未实际使用的能力也可被抽中。
- 候选权重按掌握度分档：0—99为5，100—199为4，200—299为3，300—399为2，400—499为1，500为0并退出候选池。权重在收益生成时计算并持久化。
- 目标达到500时，超出部分直接作废，不转移，不把整笔收益重抽。例如490获得25，最终为500，剩余15作废。

## 数据驱动与特殊处理器

普通能力优先使用统一数据配置。只有通用字段无法忠实表达的特殊能力才绑定受控扩展处理器；处理器必须可测试、可版本追踪并参与模拟校准。

扩展处理器不能直接写存档、绕过胜负或任意改世界状态。普通能力处理器只能返回该能力的判定参数和结果后果，由统一数值判定处理；战斗处理器只能接入 `D-COMBAT*` 已声明的转盘流程。所有随机必须由引擎提供的行动级可复现随机流产生，并记录流标识、取数顺序、结果和能力版本。

## 普通能力判定

非战斗能力直接使用统一的四档数值判定。能力记录声明适用的核心能力、难度/修正、前置、目标和可能后果；判定一次完成，结果按普通成功、大成功、普通失败或大失败进入能力或事件的具体结果数据。

第一版不建立独立的公共效果事务、能力级预检、逐项回滚或通用成本锁定系统。能力是否消耗灵性、改变状态、写入线索或触发事件，随该能力/事件的数据和统一判定结果处理；具体能力逐项设计时再填写。

## 战斗能力

战斗能力只进入已锁定的次数盘、能力盘、胜负盘和胜负后因果结算。能力的战斗权重、胜势贡献、命中效果、物品/封印物和特殊效果写在战斗能力参数中，不调用普通能力判定的事务规则。

## 能力设计顺序

先完成统一数值判定和最小能力记录，再按途径/序列逐项录入普通判定后果与战斗参数。每完成一套序列，跑批量转盘模拟并人工做原著审查；数值或能力效果若暴露底层缺口，必须回到台账重新 Grill。

当前能力记录已按 `D-ABILITYSCHEMA4` 使用显式目标选择器，未声明特殊范围时默认单一目标；效果的持续与叠加字段已按 `D-ABILITYSCHEMA5` 锁定最小规则，不得在具体能力中自行增加全局机制。
