# 世界推理与事件因果设计

2026-09-13｜设计候选 V1。继承已确认的 EW-01—18 与事件/战斗规则；本文件新增的调度、意图优先级和示例是助手设计候选，不等于玩家已审核，也不代表代码已经实现。

## 1. 玩家要感受到什么

玩家调查后，证人可能愿意作证，雇主可能转移证据，收到举报的组织可能介入；休养一周也不会让此前承诺停止计时。玩家看到的是信件、见闻、可核验线索、事件选择与后果，不是后台势力算分面板。

世界推理的职责是：从已经发生的事情，推出哪些已设计行动现在成立、哪些旧安排失效，以及玩家能够观察到什么。不是让大模型续写世界，也不是模拟全城每个人的一生。

```text
已提交事实 → 直接反应 / 到期后果 → 合法人物与组织意图
          → 同目标冲突结算 → 新事实
          → 可知见闻、传闻、案件变化 → 符合当前序列与途径的事件
```

事件选择产生事实，事实改变后续事件资格。模型只接收最后一层允许公开的内容，没有反向写入箭头。

## 2. 只保存会改变玩法的状态

| 对象 | 最小状态 | 不建立的系统 |
|---|---|---|
| 世界事实 | 稳定 ID、主体/对象、发生日期、原因、当前有效性 | 任意自然语言事实自动转规则 |
| 关键原著人物 | 已有身份、阶段、存活/可用性、地点、当前合法行动、关系与近期原因 | 无限记忆、自由生成角色脑 |
| 轻量具名人物 | 身份槽、存活/可用性、事件需要的处境、关系和原因 | 每周独立算分、完整人生模拟 |
| 组织 | 一条玩家关系阶段、一个当前议程、适用地区、当前阶段 | 平行派系、成员资源表、多套组织好感 |
| 地区 | 已发生问题的标签、相关事件引用、公开迹象 | 人口、交通、全城供需模拟 |
| 延迟后果 | 原因、最早日期/截止日期、所需条件、取消/改道方式 | 随机到期、默认一周全部删除 |
| 观察/知识 | 谁获知、来源、日期、确定/传闻、可见内容 | 知识属性直接解锁全世界秘密 |

这些都是已有 world/knowledge/events 状态的细化，不再建第二套世界数据库或任务账本。事实保留来源与因果引用即可，不要求架构哈希或文档 SHA256。

### 真相、人物所知、玩家所知分开

- 世界可以已知“账册被烧毁”，玩家在现场检查、收到可信报告或其它合法观察后才知道。
- 人物决策只读自身已经获得的观察与公共事实。引擎知道玩家秘密，不等于 NPC 能用它作决策。
- 误解必须有具体来源：证人记忆不完整、已设计谎言或误导性痕迹。误解不改变底层真相。
- 举报、传话、曝光不是所有信息自动广播。每个选择声明交出了哪些证据、交给谁；组织介入只使用收到的部分。
- 日常能力可以增加一个预先定义的观察，不自动揭开该事实的全部来源、身份和因果。
- 公开提示可以写“对方似乎开始回避你”，不能因为后台敌意状态改变就显示“幕后组织准备灭口”。

## 3. 三种推进尺度

### 每次行动与选择后的直接反应

只处理该提交真正触及的对象，例如交出证据后建立接收记录、转移物品的归属、确认救援、改变关系原因、取消已经不成立的赴约安排。不会让全城组织在每次点休养后都完整行动一次。

同一因果在一次提交内只兑现一次。即时反应只能结算声明的效果或生成后续安排，不能反复互相触发“反应的反应”直到世界自行演完。需要人物主动行动的后续通常等待周脉冲；确实紧接当前选择的危险/救援由事件图明确衔接。

### 完整周脉冲

1. 上周最后行动及已生成待办先全部解决；若已终局，不再推进新周。
2. 取当前日期到下一周日期之间的到期事项，按实际生效时间分组；不是先把所有人物推到周末再补算周中发生的事。
3. 每个时间组先应用已提交、无需再次决策的到期后果；若出现必须当场选择的已设计事件，停在该边界，处理完继续本次周脉冲。此时不能提交新的主要行动，也不提前发放下一周行动点。
4. 人物/组织在声明的周决策点选择至多一个主动意图。每个对象一周只作一次这种主动选择；恢复脉冲不能再次选择。
5. 同一时间组的意图读取同一事实快照；先解决相互冲突，再一起提交结果。后组可以读取前组结果。
6. 到达下一周日期时，按已有经济和角色规则完成周期结算并发放新周行动点；生成可知纪事、重新校验计划卡。
7. 周脉冲新产生的阻塞待办逐张解决后，才开放新周主要行动。不能因这些卡不耗 AP 就再推进一周。

跨中间日期暂停只为真实到期因果，不新增按天操作。普通一周仍是行动点用尽自动推进。周结算进度属于已有存档状态，防止重启后重复发钱、执行议程或恢复资源。

### 远方与时间跃迁

远方只推进有来源的时代节点、组织态势和公共消息；与玩家有未结承诺的远方对象仍保留该承诺的精确因果，不因离城丢失。

长期仪式跳时不循环生成数千张随机卡：先展示可知的跳时范围、生活/资产安排、未结承诺和不可逆影响；经玩家明确选择后，按已设计时间节点推进。关键选择、死亡风险和仪式中断停在真实节点；普通重复收支使用已有规则的区间结算，但收入只覆盖工作/资产资格实际成立的区间，不凭空领取百年工资。缺少长周期寿命、组织更替或仪式规则时，只把该仪式列为内容未完成，不把短周玩法一起停掉。

## 4. 人物和组织怎样决定行动

### 关键人物：阶段先限制，再排优先

先剔除违反时代、能力、地点、知识、存活状态或关系事实的行动。阶段图通常只需数个可理解阶段，每阶段少量合法意图，例如“等待可信信息—核验—处理结果—暂时不可用”。这些是阶段图的通用结构，不替代原著人物各自的实际动机。

首版候选采用可解释的离散 Utility 排序，不另建人格权重训练器。依次比较：

1. 必须履行且即将到期的已知责任；
2. 当前阶段目标的直接推进程度（直接、间接、无关）；
3. 已知风险是否可接受、所需对象是否可用；
4. 是否回应玩家刚刚提供的有效事实；
5. 是否重复上一周无变化的尝试。

这些值由人物阶段内容声明，不是全体人物都先救人或先赚钱的道德排序。同分按该人物已声明的行动优先序，不用运行时模型投票。没有合法有效行动就是等待；等待不制造新闻。

### 组织：一个议程的推进

议程可处于等待条件、核验、执行、收尾等有限阶段，但同时只有一个当前议程。相关事实可以使其转段、完成或被更紧迫的已设计议程替换；旧议程的未结责任仍作为具体延迟后果保留，不暗中变成第二套并行议程。

组织不会替玩家自动加入、交出全部证据或选择阵营。成员执行所属议程时视为同一项行动的参与者，不再以个人行动重复获得一份效果。

## 5. 同时争抢、失败与死亡

每个世界意图需明确目标、占用对象、前提、完成效果、失败效果、公开迹象与原因。只允许内容中已定义的类型，如核验报告、传递消息、转移证据、接触人物、封锁现场。

| 竞争情况 | 处理 |
|---|---|
| 相互独立 | 都执行，不因实现遍历顺序互相影响 |
| 对同一对象目标兼容 | 合并参与者，效果只提交一次 |
| 实际日期/先后条件不同 | 真正先发生的先结算，后来者面对已变化事实 |
| 同时互斥、有已设计对抗规则 | 使用该规则与可重放随机；结果生成明确成功/失败事实 |
| 同时互斥、没有对抗规则 | 不凭对象 ID 判胜负；保留争持/未达成状态，走已写的延期或玩家可介入分支 |

最后一项不是让作者永远不设计冲突：关键分支必须补足其对抗和后果后才成为正式内容。普通争持可以短暂延期，但必须有截止后的放弃/取消结果，不无限延期刷通知。

玩家在场且选择介入战斗时进入战斗盘；世界推理不根据“组织更强”暗杀关键人物。玩家单独撤退后的战斗快结算沿用战斗主题规则，不能推广成通用离屏死亡器。

原著人物死亡只接受已结算事件/战斗、可追溯玩家因果或核验过的原著基线。死亡立即使本人对话、未来赴约和能力行为失效；消息是否传到玩家是另一件事。替代者必须是新的真实身份，只承接声明可转交的普通职责，不继承死者秘密、私人承诺或原著专属台词。

原著时间节点也要重验依赖：相关人物或关键条件已被改变，就不能照播旧结局。没有适配分支的远期剧情不擅自编出新版结局，记录它不再可按原基线推定；保留现有世界事实和不依赖该节点的玩法。制作时优先补影响晋升和主要人物的分歧。

## 6. 世界如何把内容交给事件卡

世界输出的是机会条件，不是已经保证弹出的卡。调度见 [事件卡系统](EVENT_CARD_SYSTEM.md) 第 8 节。

- 刚发生且必须回应的后果：生成必达事件或结果，不进入日常随机抽奖。
- 可以调查、拜访、追索的机会：只把玩家确实获知的线索/情境入口展示出来；未选择前留在计划层。
- 不需要选择的变化：进入纪事，不为了表现世界活跃强行弹阻塞卡。
- 仍属秘密的变化：暂不展示，后续合法观察可以揭露；不显示隐藏消息条数。

同一世界事实可以引出不同途径的不同事件，但只有当前途径实际匹配的一版成为实例。缺变体不能用通用版硬顶，更不能让模型补一条能解决当前案件的新能力。

## 7. 首弧的端到端纸面走查

以下只演示既有《沉默的夜班铃》结构与本候选编排；实际检定数字、结果矩阵和对白仍读取 `FIRST_EVENT_ARC_DESIGN.md`，不另写一份奖励表。

1. 玩家经当前行动遇到梅芙，接受失踪调查。生成案件实例与已获线索；没有因此获知黄铜铃真相或值夜者内部议程。
2. 玩家查证工资/工伤事实。若明确提交了可信证据，接收者记录这部分知识；如果只保留自查，组织不能靠读取玩家背包自动介入。
3. 奥黛丽接触按现有阶段和可用性选择本人或稳定代理人。既定观察只涉及现场言行，拒绝委托仍保留独查路线。
4. 最后一次行动触发锅炉房 C 卡时先解决卡，不让周脉冲抢先焚毁玩家正在选择的现场。
5. 玩家选择先救人：按既有 C 卡矩阵处理救援、证据与危害；任何逃逸/毁证只兑现该结果声明，不由组织模拟再掷一次。
6. 若结果留下携铃逃逸且已设计追踪条件，则安排后续机会；若已收容，则移除以“铃仍在锅炉房”为条件的事件。救援、追责、危害、奥黛丽关系四轴分别记录。
7. 下周收到可信报告的组织推进当前议程。它与已经完成的玩家救援不重复发放救援效果；只处置仍存在的危害或进行必要询问。
8. 玩家只看到已知的救援回执、调查跟进和组织接触；未获知的追索行动不显示标题。模型失效时所有上述内容仍有固定文本。

该弧普通人与序列9分别成版；玩家已升序列8时不会新抽到序列9锅炉房。旧案件已提交的救援继续成立，未结内容按“转换成当前序列版本 / 世界结果 / 取消留因果”处理，不能重置案件再赚一次奖励。

## 8. 实现前只需验证的代表场景

本次为文档推演，下面是未来切片的相关验证要求，非已执行测试。

| 场景 | 应有结果 |
|---|---|
| 已打开卡后读取很久 | 日期与人物不偷偷推进 |
| 最后 AP 触发卡、卡又引发战斗 | 事件及战后即时后果先结束，再推进一次周脉冲 |
| 周中到期必选事件 | 在该日期处理，继续原脉冲；不多发一周 AP/收入 |
| 同一份证据同时被两方转移 | 只产生一个合法归属或明确争持，不复制物品 |
| 先前待办使下一张人物死亡/离城 | 下一张先重验，使用声明分支；不出现死者对白 |
| 没举报但玩家掌握全部秘密 | 组织仍不知道；不会无来源响应 |
| 晋升、迁居或改变组织 | 重新筛选，保留已兑现后果，不刷新旧奖励 |
| 原著节点依赖已被玩家改变 | 不照播旧结局，不让模型补新真相 |
| 同次提交重试、恢复周脉冲 | 复用已提交结果，意图/收入/随机不重复 |
| 可用模板不足 | 诚实给行动反馈，不借低序列或别途径凑卡 |

## 9. 内容还需要制作什么

本候选完成世界因果的工作方式，不宣称 NPC 全名册、全部原著时间节点和22条成长弧已经写完。实际制作需继续补：关键人物阶段与来源、组织具体议程、地区可用事件、逐途径逐序列卡片、重大分歧与长期仪式后果。首个实现切片只接既有调查弧所需对象，验证世界能回应玩家，再扩展内容，不先做一个无人可玩的全世界模拟器。
